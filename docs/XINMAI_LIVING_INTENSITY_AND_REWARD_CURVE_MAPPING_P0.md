## 二、为什么需要本 MAP

Phase 2 已经证明：

```text
用户表达
↓
同一生命回应
↓
回应事实被真实确认
↓
关系成立
```

现有工程也已经存在：

- Reality 身体回应；
- Life Weather；
- Inner View；
- 三次靠近；
- Choice 呼吸停顿；
- 新回应纹理；
- Crystal 身体沉积；
- Archive 与返回记忆。

当前缺口不是“没有反馈”。

而是：

```text
反馈存在
↓
各页面独立定义强度
↓
用户可能感到有些变化太弱
有些变化靠文字说明
有些变化等待时间过长
有些变化语义过早达到高潮
```

如果直接增强特效，会产生：

```text
局部更亮
↓
整体节奏失衡
↓
Crystal 变成奖励高潮
↓
生命哲学退化为游戏刺激
```

因此需要先冻结：

1. 什么叫生命强度；
2. 什么叫合法回报；
3. 哪个阶段可以达到多高的感知峰值；
4. 哪个阶段负责留下长期价值；
5. 哪些现有资产可以直接承载；
6. 哪些未来施工必须先审查。

## 三、最高定义

### 3.1 Living Intensity

生命强度不是：

- 粒子数量；
- 亮度；
- 动画幅度；
- 声音音量；
- 页面信息量；
- 用户兴奋程度。

生命强度是：

> 用户能够多清楚地感知：同一个生命，因为我的行动或现实经历，正在发生可追溯的变化。

公式：

```text
用户动作可辨认
+
世界回应可辨认
+
同一生命连续
+
变化来源可追溯
=
生命强度
```

### 3.2 Life Return

本协议中的 Reward 不指：

- 奖励物；
- 数值收益；
- 成就；
- 通关；
- 收藏完成；
- 胜利刺激。

它只指内部设计概念：

# 生命回报。

定义：

> 用户投入一次真实行动后，生命世界给出的、能够被理解且能够留下的因果反馈。

用户前台不应看到：

```text
Reward
奖励
获得
解锁
稀有
升级
```

### 3.3 核心公式

```text
我的行动
↓
世界明确回应
↓
我发现回应与自己有关
↓
生命关系发生变化
↓
变化在同一生命中留下
```

## 四、两条曲线必须分开

XINMAI 不采用传统游戏的单一刺激曲线。

必须同时存在两条不同曲线。

### Curve A｜感官振幅

回答：

> 这一刻，变化有多容易被看见、听见或感觉到。

正确曲线：

```text
安静存在
↓
发现上升
↓
关系回应形成清晰峰值
↓
照见阶段主动回落
↓
Choice 局部再起
↓
Crystal 克制沉静
↓
返回时成为低幅回声
```

它不是一路变亮。

### Curve B｜意义与持久度

回答：

> 这一变化对用户意味着什么，以及它会保留多久。

正确曲线：

```text
身份存在
↓
关系确认
↓
现实理解
↓
主动回应
↓
生命沉积
↓
长期记忆
```

意义与持久度可以逐步加深。

感官振幅不需要同步升级。

### 4.1 双曲线冻结

```text
感官振幅：
先升、后退、局部再起、最终沉静

意义深度：
持续加深

持久程度：
从当前周期走向生命历史
```

这就是 XINMAI 与传统奖励曲线的根本区别。

## 五、七级生命反馈语法

这些等级只用于内部设计审查。

不得成为用户数值、成长值或评分。

### Level 1｜Quiet Presence

阶段：

- 进入世界；
- 返回圣所；
- 当前稳态。

用户感受：

> 它在这里。

允许：

- 核心呼吸；
- 星尘缓慢流动；
- 低幅空间时间感；
- 已有痕迹微显。

禁止：

- 主动吸引注意的循环脉冲；
- 高频闪烁；
- 奖励等待感。

### Level 2｜Discovery Cue

阶段：

- 生命坐标回应；
- 星宿骨相显现；
- Reality 某处触碰身体；
- Inner View 入口出现。

用户感受：

> 这里有一处变化值得靠近。

关键要求：

- 局部；
- 有方向；
- 不提前解释；
- 不全屏增强。

### Level 3｜Relationship Response

阶段：

- Recognition 回应；
- Life Whisper StarBeast Response；
- 老用户同体回应。

用户感受：

> 它听见了我。

这是 Phase 2 的最高感官峰值。

关键动作至少应在两个可辨认通道中发生变化：

- 姿态；
- 呼吸；
- 距离；
- 星尘方向；
- 核心节律；
- 局部光质；
- 克制声音或触觉。

不是要求全部叠加。

### Level 4｜Reflective Hold

阶段：

- Gravity；
- AI Reflection；
- 保护方式理解；
- Choice 前停顿。

用户感受：

> 我开始看见自己。

这一阶段应主动降低：

- 动画密度；
- 粒子变化；
- 文案同时出现的数量；
- 声音事件。

强度来自注意力聚焦，不来自刺激增强。

### Level 5｜Lived Response

阶段：

- Choice；
- 呼吸停顿；
- 新回应空间；
- 用户确认“这一次有一点不同”。

用户感受：

> 我没有完全被旧模式接管。

表现：

- 旧节律放慢；
- 同一身体保持；
- 用户动作真正影响节奏；
- 新路径只表现为可能性。

禁止：

- 正确答案；
- 成功提示；
- 任务完成；
- 立即生成 Crystal。

### Level 6｜Quiet Sediment

阶段：

- Crystal；
- 身体纹理形成；
- Archive 入口开放。

用户感受：

> 这次经历留在了我的生命里。

表现冻结：

```text
声音：
一声

光：
一点

动作：
一次沉入

位置：
刚刚变化的生命位置

留白：
更多
```

Crystal 的意义强度最高。

但感官振幅不得高于 Relationship Response。

### Level 7｜Returning Echo

阶段：

- 老用户回归；
- Life Weather；
- Crystal 记忆；
- 人格年轮；
- 新 Reality 前的生命稳态。

用户感受：

> 它记得，但过去没有接管现在。

表现：

- 低幅；
- 长期存在；
- 可被再次发现；
- 不自动重播历史事件；
- 不恢复历史 Pressure Seed 为当前压力。

## 六、生命回报的四种合法形式

### 6.1 Response Return

用户行为：

```text
靠近
触碰
表达
```

生命回报：

```text
同一生命明确回应
```

回答：

> 世界有没有听见我？

### 6.2 Discovery Return

用户行为：

```text
观察
停留
进入内观
```

生命回报：

```text
原本模糊的生命关系被用户发现
```

回答：

> 我是否看见了以前没有看见的东西？

### 6.3 Agency Return

用户行为：

```text
停顿
保持
回应
确认差异
```

生命回报：

```text
旧路径没有完全接管
```

回答：

> 我的主动权是否重新出现？

### 6.4 Continuity Return

用户行为：

```text
理解经历
确认变化
回到生命世界
```

生命回报：

```text
身体纹理
Crystal
Archive
返回回声
```

回答：

> 这次经历是否真的留了下来？

### 6.5 禁止的回报形式

```text
数字上涨
收藏数量
稀有度
连续签到
宝箱
徽章
战力
排名
完成百分比
强迫回访
```

## 七、关键动作反馈规则

### 7.1 关键动作

以下动作属于关键动作：

- 认出星兽；
- 提交 Life Whisper；
- 明确认出 Reality；
- 主动靠近 Inner View；
- 完成一次 Choice 停顿；
- 确认新的回应确实发生；
- 将 Crystal 沉入年轮。

关键动作必须：

```text
用户动作发生
↓
当前生命事实变化
↓
至少两项可辨认反馈
↓
反馈完成后形成新稳态
```

### 7.2 普通观察动作

普通停留、浏览或轻微触碰不要求两项反馈。

允许：

- 单一光质变化；
- 单一呼吸变化；
- 局部星尘方向变化。

禁止每次触碰都制造高潮。

### 7.3 反馈完成

关键反馈的完成不能只依赖：

- 页面等待时间；
- 文案替换；
- 按钮出现；
- CSS 动画预估。

如果反馈完成会解锁新的产品事实，应优先使用：

```text
真实 Visual Outcome
用户明确确认
权威持久化 Outcome
```

计时器只能承担视觉编排或失败看门狗。

## 九、当前强度资产的真实分布

### 9.1 Renderer

当前 Renderer 已消费：

- Recognition response wave；
- Life Whisper response wave；
- Relationship settled；
- Pressure contraction；
- Recovery；
- Choice pause；
- Choice response space；
- Crystal sediment；
- Return memory。

优点：

- 同一核心与身体连续；
- 反馈不是独立 UI 特效；
- 关系回应已有真实 Outcome。

风险：

- 强度常量分散；
- 页面阶段之间缺少统一语义标签；
- 局部调亮可能破坏全局曲线。

### 9.2 Page / Host

当前页面与 Host 已拥有：

- Relationship Fact；
- Visual Outcome；
- Reality Intent；
- Inner View State；
- Choice Response Phase；
- Crystal Sediment Phase。

优点：

- 事实边界基本清楚；
- Phase 2 已经避免伪造成功。

风险：

- Choice、Trace、Crystal 的部分视觉编排仍使用局部固定时间；
- 如果未来把计时完成直接当成成长事实，会重现旧 `SETTLED` 问题。

### 9.3 CSS / Presentation

当前 CSS 已表达：

- 呼吸；
- 收束；
- 流动；
- 停顿；
- 沉积；
- 记忆回声。

风险：

- 相同透明度不等于相同意义；
- 仅降低 opacity 容易变成“弱而消失”；
- 多处独立 transition 难以形成完整强度弧线。

## 十一、声音与触觉曲线

### 声音

允许：

- Recognition 一次短回应；
- Whisper Response 一次极短生命声；
- Crystal 一声克制确认；
- 返回空间低幅环境回声。

禁止：

- 连续奖励音阶；
- 逐步升调；
- 胜利和弦；
- 高频确认音；
- 每次触碰都有音效。

Crystal 声音：

```text
不是“获得”
而是“沉入”
```

### 触觉

允许：

- 用户关键主动动作的一次轻触觉；
- Choice 保持完成时的一次微弱确认。

禁止：

- 连续振动；
- 打击反馈；
- 宝箱式震动；
- 失败震动；
- 用触觉诱导重复操作。

### Reduced Motion

Reduced Motion 不是降低产品意义。

必须以：

- 静态同体姿态；
- 空间距离；
- 局部光质；
- 纹理状态；
- 克制文案；

替代运动通道。

语义强度必须与 Motion 等价。

## 十三、是否需要新系统

结论：

```text
Reward Engine：
REJECT

Living Intensity Engine：
REJECT

新数据模型：
REJECT

用户可见强度值：
REJECT
```

原因：

1. 现有 Runtime 已承载全部关键生命阶段；
2. 当前缺口是表达校准，不是因果能力缺失；
3. 新 Engine 会复制现有状态；
4. 数值会把生命变化游戏化为属性成长；
5. 跨阶段统一可以先由协议与验收矩阵承担。

允许未来讨论：

```text
共享视觉语义类型
或
视觉 Token
```

但只有在 Phase 3 Entry Review 证明：

- 多个合法消费者确实需要；
- 当前局部事实无法安全承载；
- 不改变状态权威；
- 不产生第二套反馈链；

时，才能进入 Major Blade Prep。

## 十四、当前语义偏差与风险

### 风险 A｜克制被误解为不可见

表现：

- 反馈透明度过低；
- 动作只靠文案解释；
- 用户看不出行动与变化关系。

裁决：

```text
Refinement
按屏授权
不得全局加亮
```

### 风险 B｜强度被误解为特效

表现：

- 增加粒子；
- 放大核心；
- 增加光晕；
- 提高声音。

裁决：

```text
REJECT
除非能证明因果理解提高
```

### 风险 C｜局部计时成为意义权威

当前 Choice、Trace、Crystal 存在视觉编排计时。

计时作为 presentation orchestration 可以保留。

但禁止升级为：

```text
时间到了
↓
用户成长成立
```

如果 Phase 3 / Phase 4 施工需要依赖这些计时器解锁真实资产，必须：

```text
STOP
↓
```
