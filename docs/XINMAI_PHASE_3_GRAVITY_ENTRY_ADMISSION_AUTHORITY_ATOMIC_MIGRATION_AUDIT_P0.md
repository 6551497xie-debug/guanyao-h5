## 7. Typed Gravity Entry Authority

### 7.1 产品语义

正式定义：

> Gravity Entry Admission 证明：用户在同一生命、同一 Reality encounter 中认出了一个现实，主动靠近了生命回应位置，并已完成从 Reality 到 Gravity 的合法交接。

它不证明：

- 用户存在缺陷；
- Gravity 已经被理解；
- Six Dimension 已经观察；
- AI 已经照见；
- Choice 已经发生；
- Crystal 有资格生成；
- Phase 4 已经开始。

### 7.2 唯一权威所有者

目标：

```text
RealityToGravityEntryAdmissionController
```

职责：

- 生成唯一 `gravityCycleId`；
- 持有当前 Gravity Admission 状态；
- 校验三项身份引用；
- 校验 source Reality intent / encounter；
- 校验 admission revision；
- 校验 TTL；
- 拒绝旧周期 callback；
- 接受 Route / Host typed outcome；
- 清理或终结当前 Gravity cycle。

禁止生成者：

- Reality Host；
- Reality Presentation；
- GravityPage；
- Renderer；
- Route component；
- localStorage；
- Dynamics Input Adapter；
- Pressure Seed Adapter；
- Choice；
- Archive。

Host 只能生产申请事实。

Controller 才能建立 Admission。

### 7.3 `gravityCycleId`

唯一生成者：

```text
RealityToGravityEntryAdmissionController
```

生成时机：

> 当前 Reality 仍为 ACTIVE，用户认出的 Pressure Seed、三项身份引用与 body approach 全部校验通过，并首次请求进入 Gravity transfer 时。

禁止复用：

- `sourceReferenceId`；
- `intentReferenceId`；
- `encounterCycleId`；
- `selectedPressureSeedId`；
- candidate bundle reference；
- Choice reference；
- Crystal key。

同一次 transfer：

- 重试不生成新 ID；
- Route load 失败不生成新 ID；
- Gravity Host 失败不生成新 ID；
- 刷新不生成新 ID；
- 旧 callback 不得影响新 ID。

只有当前 Gravity cycle 正式终结，并且新的 Reality 再次被用户认出后，才能生成新 ID。

## 8. 最小状态机

目标状态：

```text
ABSENT
↓
TRANSFER_PREPARED
↓
READY_TO_ENTER_GRAVITY
↓
ACCEPTING_GRAVITY
↓
ACTIVE_IN_GRAVITY
↓
TERMINAL / CLEARED
```

失败分支：

```text
TRANSFER_PREPARED
或
READY_TO_ENTER_GRAVITY
或
ACCEPTING_GRAVITY
↓
FAILED_RETRYABLE
```

### 8.1 `TRANSFER_PREPARED`

只代表：

- 当前 Reality 仍是 ACTIVE；
- Host 的 Gravity request 已校验；
- target admission candidate 已生成；
- 原子 cutover 尚未提交。

不得：

- 导航；
- 启动 Gravity；
- 终结 Reality；
- 写历史 Seed 为当前 Active；
- 对用户声称已经进入。

### 8.2 `READY_TO_ENTER_GRAVITY`

只在原子 cutover 成功后成立。

证明：

- 当前 Reality terminal proof 已包含在同一 transfer envelope；
- 当前 Gravity Admission 已正式接管；
- 三项身份、Reality refs、Pressure refs 一致；
- Route target 固定 `/dynamics`。

它不等于：

- `/dynamics` 已 mount；
- GravityPage 已呈现；
- Six Dimension 已启动；
- Gravity 已 ACTIVE。

### 8.3 `ACCEPTING_GRAVITY`

表示：

- `/dynamics` Route 已 post-commit；
- Admission 已被 Route 接受；
- Gravity Runtime Input 已组装；
- 正在等待真实 minimum surface outcome。

### 8.4 `ACTIVE_IN_GRAVITY`

只有以下事实属于同一 transaction 时成立：

```text
同一 gravityCycleId
+
同一 admission revision
+
同一三项身份引用
+
同一 selected Pressure Seed
+
同一 body-approach proof
+
同一 Route target
+
真实 same-life surface outcome
+
真实 first Gravity observation surface outcome
```

以下不构成 ACTIVE：

- `navigate("/dynamics")`；
- Route mounted；
- GravityPage function 被调用；
- Canvas DOM 存在；
- `data-*` 存在；
- localStorage Seed 存在；
- engine snapshot 被创建；
- fixed timer 结束。

### 8.5 `FAILED_RETRYABLE`

保留：

- 同一 `gravityCycleId`；
- 同一身份引用；
- 同一 Pressure Seed；
- 同一 source Reality terminal proof；
- 同周期重试资格。

不生成新周期，不回退到 persisted Seed 旁路。

- 当前 Reality 已经 ACTIVE；
- Pressure Seed V2 已被用户认出；
- capture provenance 当前有效；
- Gravity readiness READY；
- body approach 已完成；
- visual continuity 同一身份。

Host 输出：

```text
Typed GravityEntryRequest
```

Host 不：

- 生成 `gravityCycleId`；
- 终结 Reality；
- 写 Recovery；
- 导航；
- 提交 ACTIVE；
- 启动 Gravity Engine。

### 10.2 原子事务所有者

目标：

```text
RealityToGravityCutoverTransaction
```

由 Route 层调用。

职责：

- 读取当前 Reality Intent；
- 调用 Admission Controller prepare；
- 生成单一 durable cutover envelope；
- 将 Reality terminal proof 与 Gravity ready admission 一起提交；
- 切换当前内存权威；
- 清理被 supersede 的 Reality recovery；
- 产生唯一 Route ticket；
- 失败时保持原状态或明确可恢复状态。

Route 是 transaction caller。

Route 不是 Gravity state authority。

### 10.3 Route 消费者

目标新增/适配：

```text
GravityProductionRouteEntry
```

职责：

- 消费 navigation ticket 或 Recovery Adapter 结果；
- 校验 identity；
- 校验 cycle / revision / TTL；
- post-commit 建立 `ACCEPTING_GRAVITY`；
- 从 recognized identity 恢复同一视觉与 Mother 输入；
- 向 GravityPage 投递 explicit runtime input；
- 接收 typed minimum surface outcome；
- 把 outcome 交给 Controller。

禁止：

- 从 localStorage Seed 自行创建 Admission；
- Route mount 即提交 ACTIVE；
- 直接读取 Relationship Name；
- 调用 Pressure Seed Engine；
- 执行 Choice / Crystal。

### 10.4 GravityPage

目标职责：

```text
Explicit Gravity Runtime Input
↓
Six Dimension / Gravity visual experience
↓
Typed Gravity Surface Outcome
```

目标移除的生产责任：

- 读取 `location.state`；
- 读取 production localStorage；
- 判断 admission；
- 恢复 identity；
- 自己推导当前 Reality；
- route navigation authority。

开发 fixture 可以通过独立 dev adapter 投递，不得混入 production input union。

### 10.5 Renderer

Renderer 只消费：

- same-life visual facts；
- Gravity visual facts；
- motion / reduced-motion facts。

不得消费：

- Admission state；
- Pressure Seed 原文；
- relationship state；
- route state；
- storage；
- DOM `data-*`。

## 11. Recovery Adapter 唯一边界

正式目标：

```text

Gravity Entry Recovery Adapter

消费恢复候选并重新校验

Route:
通过 Adapter API 请求恢复

Page:
零存储读取

Renderer:
零存储读取
```

Storage 内容永远只是：

```text

```

不是 Runtime 权威。

### 11.1 TTL

冻结：

```text
Gravity Admission TTL:
2 hours maximum
```

与既有 Reality Encounter Intent 上限一致。

规则：

- 刷新不延长；
- 重试不延长；
- Route load 失败不延长；
- Candidate surface 失败不延长；
- 后台切换不延长；
- 过期不生成新周期；
- 过期不清除身份或关系；
- 过期不被解释为明确离开。

### 11.2 刷新

```text
Recovery Candidate
↓
Controller 校验
↓
Recognized Identity Recovery
↓
Route 重新承接
↓
Gravity minimum surface 重新呈现
↓
恢复同一 cycle
```

Storage 中的 `ACTIVE_IN_GRAVITY` 只能是恢复候选。

Route 不能看见字段后自行宣布 Active。

### 11.3 Storage 不可用

原子 cutover 之前发现 Storage 不可用：

```text
保留当前 Reality ACTIVE
↓
显示真实非阻断失败
↓
允许同周期重试
```

不得：

- 先终结 Reality；
- 只靠 navigation state 进入；
- 生成无恢复能力的半周期；
- 写旧 localStorage 作为替代权威。

### 11.4 明确离开

Gravity Admission 只有以下事件可以终结：

- 用户明确离开 Gravity；
- 当前 Gravity observation 正式结束并进入下一阶段授权；
- 用户开始新的 Reality encounter；
- 身份失配；
- TTL 过期；
- 用户清除相关数据。

以下不是明确离开：

- 刷新；
- 普通卸载；
- 后台切换；
- 网络断开；
- Route chunk 失败；
- WebGL context lost；
- 浏览器崩溃。

## 12. Reality → Gravity 原子提交点

### 12.1 最高原则

冻结：

```text
一个 Durable Cutover Envelope
一个 Authority Switch
一个 Route Ticket
一个回滚单位
```

### 12.2 提交前

仍然成立：

```text
RealityEncounterIntent:
ACTIVE_IN_REALITY

GravityAdmission:
ABSENT / TRANSFER_PREPARED
```

用户仍在 Reality。

Gravity 不得开始。

### 12.3 原子 Commit

唯一 commit point：

> Durable Cutover Envelope 被唯一 Recovery Adapter 确认写入，并同时包含已经校验的 source Reality terminal proof 与 target Gravity ready admission。

Envelope 至少包含：

```text
sourceReality:
  intentReferenceId
  encounterCycleId
  revision
  identityReferences
  terminalReason

targetGravity:
  admissionReferenceId
  gravityCycleId
  revision
  identityReferences
  selectedPressureSeedReference
  bodyApproachProof
  routeTarget
```

Envelope 写入成功即定义：

```text
source Reality:
SUPERSEDED_BY_GRAVITY_TRANSFER

target Gravity:
READY_TO_ENTER_GRAVITY
```

随后：

- 清理旧 Reality Recovery；
- 切换 Reality Controller 内存状态；
- 激活 Gravity Admission Controller；
- 发出 Route ticket；
- 导航 `/dynamics`。

即使崩溃发生在旧 Recovery 清理之前：

- committed cutover envelope 优先；
- 旧 Reality Recovery 被标记为 superseded；
- 不得恢复两条 active chain。

### 12.4 Commit 之前失败

```text
不写 durable envelope
↓
Reality 继续 ACTIVE
↓
Gravity 保持 ABSENT
```

### 12.5 Commit 之后失败

```text
Gravity 保持 READY / FAILED_RETRYABLE
↓
保留同一 gravityCycleId
↓
允许 Route / Host 同周期重试
```

不得恢复 source Reality 为新的 active Reality。

因为用户已经完成了 transfer。

如需回到生命世界，必须是明确的安全离开，而不是隐式双权威。
