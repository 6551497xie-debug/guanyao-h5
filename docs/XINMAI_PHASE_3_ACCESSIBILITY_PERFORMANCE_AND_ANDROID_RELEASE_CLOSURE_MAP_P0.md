## 3. Three evidence tiers

### 3.1 Desktop hashed Production — normal Phase 3 readiness channel

Desktop Production is the primary repeatable evidence channel for:

- hashed JS/CSS, with Vite client, source entry, Acceptance, Fixture and fault-injection assets equal to `0`;
- keyboard-only reachability, focus order, focus visibility, landmarks, headings, native control names and status-region behavior;
- 200% native browser zoom and 320×568, 360×800, 390×844 and 430×932 reflow;
- Motion / Reduced Motion semantic parity when the operating system or browser exposes a native preference;
- current typed outcomes, single Host / Presenter counts, recovery, refresh, Back / Forward and Direct URL protection;
- desktop performance timing and background pause.

Desktop evidence may close `DESKTOP_PHASE_3_READINESS`. It cannot claim Android Chrome, TalkBack, touch exploration, device thermals or Android system Remove Animations.

### 3.2 Android Emulator — platform-composition supplement

An already valid emulator may supplement:

- Android Chrome viewport and font rendering;
- touch-target geometry and scroll ownership without automated product gestures;
- Motion / native Remove Animations composition;
- WebGL / Static resource counts and visible Android graphics corruption;
- lifecycle behavior under refresh, background and route restoration.

Emulator evidence cannot replace physical TalkBack gestures, physical-device performance/thermal observations, vendor WebView/Chrome behavior, vibration or power behavior. Missing emulator availability does not invalidate Desktop readiness.

### 3.3 Physical Android official Chrome — final Android Release Gate

Physical Android is required before the product may claim Android release support or global Phase 3 closure for Android. The final gate covers:

- official Chrome, immutable hashed Production bundle and legal canonical product state;
- Motion and native Remove Animations using the same source, render-plan, body, Crystal, Imprint and node references;
- TalkBack focus entry, left/right exploration order, double-tap activation, state announcements and four-consumer reading;
- real touch targets, 200% / system text enlargement, narrow reflow, scroll ownership and no toolbar-caused false product verdict;
- p95 Motion frame time, first trusted Static time, background pause, thermal stability and visible corruption;
- Save-Data and resource degradation without loss of canonical meaning;
- Android settings restored and temporary previews/mappings cleaned.

If physical evidence requires manual gestures or system settings, V5 must stop at one precise checkpoint. Desktop readiness may remain `PASS`, while `ANDROID_RELEASE_READINESS` stays `EXTERNAL EVIDENCE HOLD`.

## 4. Accessibility closure contract

### 4.1 Target and evidence language

The release target is WCAG 2.2 AA for the web experience. V5 may say `targeted checks PASS` only for criteria actually exercised; it must not claim full conformance from source inspection or a single screen reader.

The minimum evidence set is:

| Area | Required result |
| --- | --- |
| Keyboard | Every required native control is reachable in meaningful order; no trap; route transition moves focus to a meaningful destination; canvas does not become a parallel control when native control owns the action. |
| Focus | Focus indicator remains visible at normal size, narrow viewports and 200%; no overlay intercepts the focused control. |
| Names and roles | Controls expose product-language names; technical IDs, hidden SVG and WebGL content are not announced. |
| Landmarks and headings | One coherent main region and ordered headings; scene semantics supplement rather than duplicate page content. |
| Status announcements | One polite atomic owner per transition; first formation may announce once; refresh/recovery remains silent; SAFE_WITHHELD is truthful and actionable. |
| Contrast | Normal text target at least 4.5:1; large text and essential non-text boundaries at least 3:1. Measured values must be recorded, not inferred by appearance. |
| Reflow | At 200% and 320px width: no horizontal page scrolling, one vertical scroll owner, text/control reachability preserved, no content overlap or clipping. |
| Target size | Primary touch controls target WCAG 2.2 24×24 CSS px minimum; product-critical Crystal/Continue controls retain accepted center/corner hit evidence and do not depend on a visual-only canvas target. |
| Reduced Motion | No essential meaning depends on motion; Static keeps the same facts, hierarchy, controls and spatial ownership; recovery does not replay. |

VoiceOver may close the Apple desktop semantic channel when actually run. TalkBack remains the physical Android Release Gate; semantic-tree inspection alone must be labelled `PARTIAL`.

1. Reduce FAR density/sampling and optional post-processing.
2. Clamp DPR and stop background rendering.
3. Select trusted Static on Reduced Motion, unavailable/failed WebGL or resource pressure.
