## Evidence and first causal break

The current Ownership component contains one real native Crystal `BUTTON` with a stable accessible name and `aria-pressed` state. It is nested under `.xinmai-crystal-ownership__scene[aria-hidden="true"]`. The same button contains an SVG separately exposed as `role="img"` with its own label.

The browser accessibility snapshot therefore omits the button name even though the button remains visually present, enabled and keyboard-focusable. This is a structural accessibility-tree exclusion, not an Ownership state, renderer, Growth, Storage or copy failure.

```text

  -> XinmaiCrystalFormationOwnershipMoment
  -> real native Crystal BUTTON
  -> ancestor aria-hidden=true               <-- first causal break
  -> button name/state excluded from a11y tree
```

The nested labeled SVG is a second semantic description of the same visual object. Once the button is restored to the accessibility tree, keeping the SVG exposed would risk duplicate reading. It must remain decorative inside the button.
