## 0. 总裁决

当前产品已经拥有一套一致的深空主题、稳定星点拓扑、真实生命身份、C1 Crystal Formation / Ownership，以及 C2 Canonical Body Imprint / Single Presenter；但从 Genesis 到 Reality、Gravity、Choice、Departure / Return 与 Ownership，用户仍主要经历多个全屏页面依次替换，而不是在一个持续存在的生命世界中靠近、看见、认出、选择、离开并回来。

五张用户截图与当前生产源码共同证明：

1. **已有视觉主题**：深黑星空、暖白生命核心、天青与暖金、东方语义与克制文案已经形成品牌连续性。
2. **已有局部因果闭环**：C1/C2 的 Formation、Ownership、Body Imprint、Single Presenter 与恢复语义已经关闭。
3. **尚未成立全局空间体验**：多个页面各自持有 Canvas、相机、静态替代表面与文字编排；路由切换仍会重建世界呈现。
4. **尚未成立语义物理化**：不少状态主要由整屏字幕解释，生命身体、遮蔽、力场、节点与空间变化没有持续承担意义。
5. **下一刀不能直接施工视觉**：如果直接在各页面追加视差、Shader 或粒子，会固化多 Host、多相机与多 Presenter 的结构，增加 C1/C2 回归风险。

## 3. B｜唯一 Continuous Scene Host

### 3.1 正式原则

Genesis → Reality → Gravity → Choice → Departure / Return → Ownership 只允许一个持续生命世界。路由变化表示观察责任变化，不表示世界重建。

目标结构：

```text
existing typed identity / lifecycle / growth facts
                    ↓
XinmaiContinuousScenePresentationResolver（纯函数、只读）
                    ↓
XinmaiContinuousSceneHost（唯一世界 / 相机 Owner）
         ├─ FAR Environment Presenter
         ├─ MID C2 Same-Life Body Presenter（唯一）
         └─ NEAR Stage Interaction Presenter（当前唯一可触对象）
                    ↓
Page copy / accessible semantics / controls
```

### 3.2 Scene Host 的唯一职责

Continuous Scene Host 只负责：

- 持有稳定世界拓扑与相机轴；
- 选择 Motion WebGL 或 Semantic Static 执行方式；
- 挂载唯一 C2 Same-Life Body Presenter；
- 把当前阶段的 typed presentation facts 投影到 FAR / MID / NEAR；
- 提交可信 Presenter proof；
- 在路由切换中保持或确定性恢复相同世界构图；
- 在不可用时输出 SAFE_WITHHELD。

它不得：

- 生成 Identity、Pressure、Observation、Choice、Departure、Return、Fact、Eligibility、Crystal 或 Imprint；
- 从 Page、DOM、CSS class、动画、粒子、相机位置或时间轴反推事实；
- 写 Storage；
- 让摄像机或 Shader 成为产品 Authority；
- 创建第二个 Same-Life Body Presenter；
- 修改 C1/C2 的 Public Outcome 或 Canonical IDs。

### 3.3 未来只读输入契约

未来 Resolver 只能消费现有 typed facts：

| 输入域 | 现有正式来源 | 用途 |
| --- | --- | --- |
| 世界与身份 | `sourceReferenceId`、render plan、StarBeast Identity、Mansion Coordinate | 稳定世界与相机轴 |
| Genesis | `GenesisProductionVisualCalibrationBundle`、recognition / presence facts | 显现与认出阶段 |
| Reality | typed Reality admission、Pressure Recognition Receipt | 当前现实进入同一身体 |
| Gravity | Gravity Admission、Observation Resume / Recognition Decision | 惯性场与可见遮蔽 |
| Choice | `ChoicePresentationReadinessDecision`、Action Route Candidate | 保护 / 收益 / 代价的可比较力场 |
| Departure / Return | Explicit Departure / Return typed proof 与 lifecycle decision | 向外打开、休眠、回来 |
| Growth | Lived Response Fact、Eligibility、Formation Receipt | 形成前后因果 |
| Ownership | `XinmaiCrystalOwnershipPresentationDecision` | 事务确认后的 Crystal 形成与拥有 |
| Same-Life | `XinmaiSameLifeSurfaceFacts`、Canonical Body Imprint Decision | Body / Imprint / stable node |

Resolver 输出只能是只读 Presentation Plan，例如：当前空间轴、三层可见职责、唯一可触对象、文字锚点、Motion policy 与 Safe-Withheld reason；不得成为第二状态机或持久化记录。

### 3.4 路由与消费者裁决

| 路由 / 表面 | 未来职责 | 是否持有世界 | 是否持有身体 | 是否可持有操作 UI |
| --- | --- | --- | --- | --- |
| `/launch-lab` Birth / Return / Ownership | 提供输入、回访与 C1 Ownership 消费 | 否，消费 Scene Host | 否，消费 C2 Presenter | 是，必要输入与确认 |
| `/genesis` | 消费出生坐标、显现与 Recognition facts | 否 | 否 | 是，靠近、认出、进入现实 |
| `/reality` | 消费 Reality / Pressure facts | 否 | 否 | 是，当前现实节点 |
| `/dynamics` Gravity / Choice | 消费 Observation / Choice facts | 否 | 否 | 是，比较与选择 |
| Departure / Return | 消费 lifecycle proof | 否 | 否 | 是，明确离开 / 回来动作 |
| `/archive` | 消费历史 Imprint 与同体 references | 否 | 否 | 是，历史条目与返回 |

Scene Host 应位于生产 App Shell / route layout 的持久层。页面成为 typed facts 与交互责任的消费者，不再各自创建世界 Canvas。

### 3.5 现状为何需要迁移审计

- Genesis 与 Same-Life 使用不同 Host 契约；
- Reality、Gravity、Returning、Archive 会各自重新挂载 `RealityLifeUniverseCanvas`；
- LaunchLab 同时保留自有 `light-field` Canvas；
- Gravity 在 continuity 缺失时可退到 `CosmicPageStarField`；Archive 也有共享视觉 fallback；
- AppShell 只标记 surface，不持有统一相机与世界生命周期；
- 当前存在按页面清理 / 创建 Renderer 的生命周期，不能靠 CSS 层叠安全合并。

因此 V1 是 Consumer / Host 原子迁移，不是绿色视觉修正。

## 4. C｜三层 2.5D 深度语法

### 4.1 不变量

1. 同一相机轴：出生宿方向、生命核心位置、身体朝向与 Imprint 节点跨阶段不重置。
2. 同一层级责任：FAR 建立尺度，MID 证明同一生命，NEAR 只承载当前动作。
3. 单一注意中心：任一时刻最多一个 NEAR 可触对象。
4. 深度不靠 blur 冒充；必须由尺度、遮挡、速度、对比、边缘清晰度与视差共同成立。
5. 完整圆环、外部轨道、传送门、机械 HUD 与随机漂移不是深度语法。

### 4.2 归一化层间规律

以下为 Presentation 目标范围，不是 Shader 参数或业务状态：

| 规律 | FAR 环境尺度 | MID 同一生命 | NEAR 当前可触对象 |
| --- | --- | --- | --- |
| 空间职责 | 宇宙尺度、稳定星宿拓扑、极慢天地痕迹 | 身体、核心、经络、关系名、长期 Imprint | 当前节点、裂纹、压力入口、选择力场、Crystal |
| 屏幕占比 | 单个元素通常 ≤ 1.5%；整体覆盖全场但不形成边框 | 身体可读包围盒为短边 42–64%；核心始终可见 | 当前对象 6–18%；命中责任最小 44 × 44 CSS px |
| 速度比 | `0.05–0.18` | `0.20–0.45` | 用户动作耦合；无操作时 `0–0.20` |
| 视差响应 | `0.08–0.18` | `0.35–0.55` | `0.75–1.00`，但不得摇晃镜头 |
| 边缘清晰度 | `0.25–0.50` | `0.65–0.90`；经络必须可追踪 | `0.85–1.00`；当前对象可明确指出 |
| 相对亮度 | `0.12–0.32` | `0.45–0.75` | `0.70–1.00`；不得高饱和奖励爆光 |
| 遮挡 | 永远位于身体后方；不得盖住正文或操作 | 可遮住 FAR；核心、身份锚点与当前 Imprint 不被永久遮挡 | 可短暂越过 MID，静止后遮挡身体面积 ≤ 12% |
| 光照衰减 | 大范围、低频、无硬边 | 由核心向经络自然衰减；身份形体不因阶段换皮 | 局部接合光；离节点越远越弱，不扩张为全屏光晕 |
| 数量 | 稳定拓扑，可按性能确定性采样 | 永远一只身体、一个核心 | 一次一个主动作；历史痕迹退入 MID |

### 4.3 相机纪律

允许：

- “靠近”时沿现有生命节点小幅收束；
- Recognition 后形成共同朝向；
- Departure 时景深向外打开；
- Return 时恢复同一相机轴与节点。

禁止：

- 摄像机巡游、环绕展示、摇晃与快速推拉；
- 路由进入时从默认镜头重新开场；
- 用摄像机运动掩盖身体或事实缺失；
- 将滚动位置当相机 Authority。

### 4.4 Reduced Motion 的空间等价

Reduced Motion 下：

- 速度与自动视差可以降为 0；
- FAR / MID / NEAR 的尺度、遮挡、边缘、亮度与光照衰减必须不变；
- 同一 Body / Imprint / Node / Action Route 构图不变；
- 通过静态层次与结构差解释状态，不靠 opacity-only；
- 不删除当前可触对象，不把语义退回纯文字。

## 5. D｜语义 → 物理变化映射

| 生命动作 | typed input（现有 Authority） | 只读 Presentation Outcome | 物理变化 | 用户动作 | 禁止 |
| --- | --- | --- | --- | --- | --- |
| 靠近 | Presence Approach / Reality Inner View typed readiness | `APPROACH_AVAILABLE / APPROACHED / WITHHELD` | 相机与 NEAR 锚点向同一身体节点收束，FAR 变化极小 | 触摸 / 键盘激活明确节点 | 点击 Canvas 任意位置推进 Authority；靠近生成 Identity |
| 看见 | Pressure seed / 当前生命天气 typed presentation facts | `OCCLUSION_REVEALED` | 原遮蔽结构在 MID / NEAR 分层显影；身体保持 | 用户靠近后观察 | 新建卡片替代身体；随机生成“问题” |
| 认出 | Recognition typed outcome / Receipt | `NODE_RESONANCE_STABILIZED` | 不稳定节点收敛为稳定共振，核心位置不变 | 明确认出 | 动画完成即确认；文案出现即确认 |
| 选择 | `ChoicePresentationReadinessDecision` + Action Route Candidate | `CHOICE_FIELD_PRESENTED` | 保护、收益、代价形成双向可比较力场；旧路径仍可见，新路径不被美化 | 用户明确选择 | 系统评判好坏、给最佳答案、力场替用户提交 Choice |
| 离开现实行动 | Explicit Departure Receipt + reconciliation decision | `WORLD_OPENED_TO_REAL_LIFE` | NEAR 选择收存至同体节点，空间向外打开，生命不消失 | “带着这一步，回到生活” | 伪造行动完成、Crystal 形成、页面关闭当离场 |
| Return / Fact | Explicit Return + Lived Response Fact | `SAME_BODY_RETURNED_WITH_RESPONSE` | 同一身体、同一节点和未结晶痕迹恢复；回应选项靠近节点展开 | 用户明确回来并选择真实结果 | Return 自动产生 Fact；NOT_ATTEMPTED / DECLINED 被惩罚化 |
| Formation | Eligibility + Formation Receipt，成功权威 `IDB_TRANSACTION_COMPLETE` | `FORMATION_CONFIRMED_FOR_PRESENTATION` | 仅事务成功后，原 Choice 节点内聚成 Crystal | 用户确认事实后观察 | RAF / timer / frameCount / DOM mounted 证明成功 |
| Ownership / Imprint | C1 Ownership Decision + C2 Canonical Body Imprint Decision | `OWNERSHIP_PRESENTED / IMPRINT_AVAILABLE` | Crystal 半嵌入同一经络节点；局部天青结晶与极弱暖金接合；经络继续通流 | 用户可触摸 Crystal，并明确离开证据视图 | 外轨悬浮、闭合圆环、第二身体、恢复时重播 Formation |

每项视觉结果都是 Authority 的只读镜像；用户动作只能调用既有 Controller。Presentation 不得回写或自行补造 typed fact。

## 6. E｜文字与控件层级

### 6.1 文字从“字幕卡”退为“空间注释”

文字分为三类：

| 层级 | 责任 | 位置 | 视觉权重 |
| --- | --- | --- | --- |
| 对象注释 | 解释当前节点 / 力场 / Crystal | 靠近对应对象，不遮挡核心 | 次于对象，高于环境 |
| 状态说明 | 表达 pending / confirmed / withheld | 稳定状态区，读屏可到达 | 克制但满足对比 |
| 责任确认 | 出生输入、Choice、Departure、Fact、Ownership Continue | 明确控件区 | 可见、可聚焦、真实命中 |

整屏居中文字不得继续承担唯一的状态表达。截图 3–5 的“空黑 + 字幕”属于需要退出的路径。

### 6.2 出生时间输入

出生时间是必要系统输入，可以保留滚轮或其他原生可访问控件，但必须明确：

```text
用户调整时间
→ 生命坐标候选同步在现有世界中移动 / 收束
→ 用户确认
→ 既有 Authority 建立正式身份来源
```

输入控件不得伪装成“摸星星即可完成”的空间动作。星河回应只能镜像当前已输入值，不能替代确认责任。

### 6.3 胶囊按钮裁决

应退出第一认知层：

- 单纯推进字幕的“下一步”；
- 重复场景已表达事实的说明按钮；
- 仅为美术节奏存在的全宽胶囊；
- 把 Canvas 全面设为模糊按钮的路径。

必须保留明确控件：

- 出生时间确认；
- Recognition 明确确认；
- Choice；
- Explicit Departure / Return；
- Lived Response 四类结果；
- Crystal Ownership / Continue；
- SAFE_WITHHELD 重试或安全返回。

保留控件必须最小 44 × 44 CSS px，中心与四角命中真实交互元素，并具备可见焦点。

### 6.4 布局与无障碍边界

- 禁止大面积空黑等待超过一个有意义状态转换；等待必须保留同一身体 / 核心与真实状态说明。
- 320 × 568 至 430 × 932 不得横向裁切；原生 200% 允许纵向滚动，但标题、主体与操作必须可恢复。
- 关键文字 ≥ 4.5:1；承载含义的身体节点、连接、焦点 ≥ 3:1。
- 文字不能只靠低透明度；截屏 5 的横向溢出必须在后续刀中归零。
- Scene Canvas / SVG 默认对辅助技术静默；同一 typed facts 由单一 Semantic Mirror 表达。
- live status 只在真实状态转换时播报一次；刷新 / Back / recovery 不重播“新形成”。
- 阅读顺序遵循：同一生命 → 当前变化 → 当前可做动作 → 状态说明。
- 截图不能证明真实读屏与命中，必须在 V5 使用 VoiceOver / TalkBack 与键盘实测。

## 7. F｜Motion / Reduced Motion / Fallback

### 7.1 正式三态

| 模式 | 执行 | 产品事实 | 成功证明 |
| --- | --- | --- | --- |
| WebGL Motion | Continuous Scene Host + 唯一 WebGL Same-Life Body Presenter | 同一世界、同一身体、同一 typed facts | Presenter commit proof；正确 references；Host / Body count 均为 1 |
| Semantic Static | 同一 Host 构图的静态 FAR / MID / NEAR；唯一 Static Same-Life Body Presenter | 与 Motion 完全相同，只移除运动 | WebGL Context 0；Static Presenter 1；相同 references 与构图 |
| SAFE_WITHHELD | 不可信世界 / 身体不呈现成功；保留克制语义与可恢复资产 | 没有伪成功 | typed failure / policy outcome |

### 7.2 唯一成功 Owner

- Scene Host 负责世界与相机 Presenter proof；
- C2 Same-Life Host 仍负责唯一身体 Presenter proof；
- 上层只在两份 proof 与当前 typed facts 完整匹配后得到公共 Presentation 成功；
- 不新增第二 Growth / Identity / Relationship Authority；
- 不用 `frameCount`、RAF、DOM connected、CSS class、动画结束、计时器或 Console 无错误证明成功。

### 7.3 Failure 纪律

- 原生 Reduced Motion 在创建 WebGL Context 前选择 Static；
- WebGL 初始化或运行失败必须先退出 Renderer / RAF / listener，再挂载同一 Static Host；
- 无可信 Presenter 时 SAFE_WITHHELD；
- Failure 不得退回通用星空壁纸并暗示“同一世界已呈现”；
- Static 不使用闭合椭圆、外轨、七条独立 blur 或纯文字替代身体。

## 8. G｜性能与资产策略

### 8.1 先空间语法，后 Renderer 技术

V1/V2 不以 Shader 为起点。先冻结同一 Host、相机轴、三层职责、静态构图与 typed mapping，再决定现有 Canvas / Three.js / Shader 的最小执行方式。

禁止：

- 为“高级感”增加粒子数量；
- 随机漂移、强 bloom、全屏 blur、摄像机摇晃；
- 新机械圆环、外部轨道或通用星空壁纸；
- 新贴图、模型或音频绕过资产 provenance；
- Crystal 离开身体成为收藏资产。

### 8.2 移动端确定性层级

现有 `LIFE_UNIVERSE_STAR_FIELD` 的 420 点拓扑保持唯一，不重生成。性能降级只能确定性采样其子集：

| 层级 | FAR 可见采样 | MID 身体 | NEAR | 后处理 |
| --- | --- | --- | --- | --- |
| High | 最多 420，按三深度层绘制 | 完整核心 / 经络 / Imprint | 当前对象完整 | 仅局部、单次轻量 glow |
| Medium | 稳定 210 点子集 | 身体拓扑与所有合法 Imprint 不减 | 当前对象完整 | 无全屏后处理 |
| Low / Save-Data | 稳定 96 点子集 | 核心、主经络、节点、Imprint 必须保留 | 当前对象完整 | 0 |
| Static | 0 个持续动画粒子；保留稳定坐标标记 | 唯一静态身体 | 静态结构差 | 0 |

采样不得改变 28 宿坐标、生命核心、Body Reference、stable node 或 Imprint 数量。

### 8.3 后续性能预算

| 项目 | 冻结门槛 |
| --- | --- |
| 首个可信静态生命表面 | 中档 Android 冷启动目标 ≤ 2.5s；超限先呈现合法 Static，不显示空黑 |
| Motion 帧预算 | 中档 Android p95 ≤ 22ms；低于门槛只能降 FAR / 后处理，不减身体事实 |
| DPR | 沿用现有上限 2；适配只能改变采样质量，不改变身份与构图 |
| V1 新增纹理 / 模型 | `0`；优先复用确定性几何与现有资产 |
| V1 新增压缩 JS | 目标 ≤ 80KB gzip；超过需单独性能裁决 |
| 新增 GPU 常驻内存 | 目标 ≤ 32MB；不得用离屏全尺寸多层制造景深 |
| 后台 / 页面隐藏 | 停止 RAF 与持续粒子更新；不释放 canonical facts |
| Save-Data | 直接 Low / Static；不下载装饰资产 |
| 热量 / 电量 | 只降 FAR、DPR 与后处理；不得进入不同产品状态 |

这些是后续 Push Gate 的目标预算，不是本 MAP 已验证结果。
