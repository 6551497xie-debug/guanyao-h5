## 五、当前真实竞态与根因

### 5.1 Refresh 竞态

```text
t0  Admission ACTIVE revision = n
t1  Host 生成 observationRef = cycle:n
t2  用户明确认出
t3  Page-local innerViewRelation = CONFIRMED
t4  用户刷新
t5  Admission Recovery 将 ACTIVE → ACCEPTING
t6  Admission revision = n + 1
t7  Host 生成 observationRef = cycle:n+1
t8  Page-local state 全部重新初始化
t9  用户可重新认出并再次提交 Choice
```

### 5.2 为什么 Growth 去重不能完全兜底

Choice 稳定 ID 当前包含：

```text
sourceReferenceId
sourceEncounterCycleId
gravityCycleId
gravityObservationReferenceId
```

当 `gravityObservationReferenceId` 因 Admission revision 改变时：

```text
第一次 Choice ID
≠
刷新后的 Choice ID
```

因此 IndexedDB 对同一个 Choice ID 的幂等保护无法识别：

> 这其实仍然是同一次 Observation。

### 5.3 多标签竞态

`sessionStorage` 是标签页会话级恢复候选。

它不能提供：

- 同源多标签全局当前 Observation；
- 新 Encounter 对旧标签的原子 fencing；
- Choice 创建与 Checkpoint 校验的同事务一致性；
- 旧标签 late write 的全局拒绝。

若只在 `sessionStorage` 增加 Checkpoint：

```text
Tab A：
OBSERVATION_RECOGNIZED

Tab B：
仍然 OBSERVATION_AVAILABLE

Tab B：
可能继续持有旧 Page 状态
```

即使两个标签拿到同一个 Reference，仍缺少全局当前 lineage 与新 Encounter 替换校验。

### 5.4 根因裁决

```text
根因一：
Observation ID 由 Host 按可变 Admission revision 派生

根因二：
用户 Recognized 事实只存在于 Page

根因三：
Entry Recovery 只恢复 Admission

根因四：
Choice 创建不验证 Canonical Observation Checkpoint

根因五：
缺少跨标签 current lineage fencing
```

## 六、产品语义边界

### 6.1 Observation Lineage

Observation Lineage 回答：

> 这一次用户正在观察的是哪一个 Gravity Encounter 中、由哪一个 Reality / Pressure provenance 形成的同一处生命收紧。

它不回答：

- 用户是否人格有问题；
- 用户是否完成六维；
- Choice 是否正确；
- 现实行动是否发生；
- Crystal 是否形成。

### 6.2 Observation Checkpoint

Checkpoint 只回答：

```text
OBSERVATION_AVAILABLE：
同一生命、同一 Reality / Pressure provenance 的 Gravity 观察表面已经真实可用。

OBSERVATION_RECOGNIZED：
用户已经明确认出本次 Gravity Observation。
```

本刀不冻结第三个 Checkpoint 状态。

Choice Ready 必须派生为：

```text
OBSERVATION_RECOGNIZED
+
当前正式 Choice presentation 资格
+
不存在已提交 Choice
```

不得持久化一个新的：

```text
CHOICE_READY = true
```

### 6.3 用户明确认出

当前正式用户动作包括：

```text
CONFIRMED
SELF_NAMED
```

两者都可生产：

```text
OBSERVATION_RECOGNIZED
```

允许保留最小 provenance：

```text
USER_CONFIRMED
USER_SELF_NAMED
```

禁止保存：

- 自命名原文；
- 页面按钮文案；
- AI 解释；
- 六维浏览序列；
- 点击轨迹。

### 6.4 Checkpoint 不是 Growth Fact

```text
Gravity Observation Checkpoint：
体验连续事实

Choice Action Intention：
行动意愿

Lived Response Fact：
用户确认的现实行动事实

Crystal Eligibility：
成长沉积资格
```

四者不得合并。

## 七、Observation ID 生命周期冻结

### 7.1 唯一生成者

```text
唯一生成者：
Gravity Encounter Continuity Controller

实际接入点：
prepareGravityEntryTransfer
首次建立新的 Gravity Encounter 时
```

生成：

```text
gravityObservationReferenceId
```

同时生成：

- `admissionReferenceId`；
- `gravityCycleId`；
- Observation Reference。

三者在同一新 Encounter 创建动作中形成。

禁止生成者：

- GravityPage；
- GravityProductionSurfaceHost；
- Renderer；
- Route；
- Recovery Adapter；
- Admission revision；
- Surface outcome；
- Browser History；
- Storage migration；
- Choice Controller。

### 7.2 Reference 形态

推荐：

```text
gravity-observation:<opaque-id>
```

禁止继续使用：

```text
gravity-observation:<gravityCycleId>:<admissionRevision>
```

Reference 必须不包含会变化的：

- Admission revision；
- Surface attempt revision；
- 动画模式；
- Reduced Motion；
- 时间步骤；
- 页面挂载次数。

### 7.3 保持规则

以下情况保持同一 Reference：

- Admission READY → ACCEPTING；
- Admission ACCEPTING → ACTIVE；
- ACTIVE 恢复为 ACCEPTING；
- Retry；
- Refresh；
- Back / Forward；
- Reduced Motion；
- Renderer 重建；
- WebGL context 恢复；
- Typed Surface 重试；
- Page 卸载；
- 同一周期再次进入 `/dynamics`；
- 同一标签或多标签读取同一 Current lineage。

### 7.4 关闭规则

Observation Lineage 只因正式事件关闭：

```text
Choice Action Intention 原子提交成功
明确离开当前 Gravity Encounter
Admission 正式过期
Identity / provenance 正式失配
用户主动清除数据
旧 Encounter 被正式终结
```

普通 cleanup 不是关闭。

### 7.5 替换规则

只有全部满足才允许新 Lineage：

```text
新 Reality Encounter 已正式 ACTIVE
+
新 Pressure provenance 已由用户认出
+
新 Gravity Admission 已正式建立
+
旧 Observation / Choice 生命周期已关闭或被正式消费
+
Controller 在 Canonical Transaction 中确认可替换
```

不得因以下事件替换：

- 刷新；
- 时间经过但 TTL 尚未过期；
- Back / Forward；
- Admission revision；
- Surface retry；
- Renderer retry；
- Reduced Motion 切换；
- Route remount；
- Tab visibility change；
- 网络恢复。

### 8.1 Record key

推荐使用：

```text
recordId = CURRENT:<sourceReferenceId>
```

目的：

- 同一生命最多一个当前 Observation lineage；
- 新 Encounter 替换必须读取最新记录；
- 旧标签写入时必然看见新的 Reference；
- 不依赖 `createdAt` 选赢家；
- 不需要 partial unique index。

同时建立唯一索引：

```text
gravityObservationReferenceId
```

### 8.2 Revision

必须区分：

```text
gravityObservationLineageRevision：

checkpointRevision：
Checkpoint 从 AVAILABLE → RECOGNIZED 的 revision

Admission revision：
Route / Surface attempt 的接收 revision
```

三者不得互相冒充。

## 九、Recovery Owner 方案比较

### Option A｜只扩展 Gravity Entry Recovery Adapter

方案：

```text
同一 sessionStorage Snapshot
加入 Observation Checkpoint
```

优点：

- 修改范围较小；
- 同标签 Refresh 容易恢复；
- Direct URL Admission 边界自然保留。

缺点：

- `sessionStorage` 不提供跨标签 Canonical current lineage；
- Choice 位于 IndexedDB，无法同事务验证；
- 新 Encounter 与旧标签之间缺少 fencing；
- Page 可能看到一份标签级旧 Snapshot；
- 无法证明不同标签不会提交不同 lineage。

裁决：

```text
REJECT
```

### Option B｜独立 Checkpoint Storage，由同一 Controller 管理

方案：

```text
Entry sessionStorage
+
新的 Checkpoint session/local Storage
```

优点：

- 语义隔离；
- 可独立版本化。

缺点：

- 形成第二 Gravity Recovery Record；
- Admission 与 Checkpoint 可能半写；
- Choice 与 Checkpoint 无同事务；
- localStorage read-modify-write 无跨窗口原子保证；
- 需要另一个冲突裁决权威。

裁决：

```text
REJECT
```

### Option C｜只读现有 Growth Assets 派生

方案：

```text
Choice / Fact / Receipt
→ Resume
```

优点：

- 不新增资产；
- Choice 后恢复完整；
- 不改变 Storage。

缺点：

- Choice 前仍无法区分 Available 与 Recognized；
- 无法恢复用户明确认出；
- 无法让 Choice 创建验证当前 Observation；
- 无法消除 revision-derived Observation ID。

裁决：

```text
KEEP AS HIGHER-PRIORITY READ
NOT SUFFICIENT AS OWNER
```

### Option D｜Session 生命周期 Checkpoint，不做跨标签

优点：

- 实现快；
- 低存储成本。

缺点：

- 不符合已冻结多标签与旧周期要求；
- 旧标签无法被新 Encounter fencing；
- 仍可能出现两个成功的用户表面；
- 商业上会损害“我的行动只形成一次”的信任。

裁决：

```text
REJECT
```

### Option E｜IndexedDB Canonical 关联记录

方案：

```text
现有 IndexedDB 数据库
+
独立 Gravity Observation Continuity Store
+
与 Growth Canonical Store 重叠的 readwrite transaction
```

优点：

- 同源多标签事务串行；
- Recognition 与 Choice 可读写同一事务域；
- 新 Encounter 可以 fence 旧 lineage；
- Growth Envelope 无需混入 Checkpoint；
- Eligibility 权威不变；
- Transaction complete 后才返回成功；
- Direct URL 仍需 Admission；
- 不需要 Web Lock 或 localStorage CAS。

代价：

- IndexedDB schema version 需要升级；
- Entry、Host、Page、Choice 与 Growth Store 必须同提交适配；
- `blocked` / `versionchange` / abort 必须有 typed failure；
- Store 命名需要明确“物理共域不等于 Growth 语义所有权”。

裁决：

```text
RECOMMENDED
```

## 十二、原子事务边界

### 12.1 新 Encounter 建立

Controller 首次建立 Admission 时生成：

```text
admissionReferenceId
gravityCycleId
gravityObservationReferenceId
```

Observation Reference 写入 Admission V2 与 Route Ticket。

此时它只是当前 Admission 绑定的候选 lineage reference。

不得向用户声称 Observation Available。

### 12.2 Surface Available 事务

最低 Typed Surface 成立后：

```text
IDB readwrite transaction
↓
读取 Current Observation Record
↓
读取 Growth Canonical Envelope
↓
校验：
identity
Reality encounter
Pressure provenance
admissionReferenceId
gravityCycleId
stable observationReferenceId
不存在更高优先级 Choice / Fact / Receipt
旧 current lineage 可被合法替换
↓
写 Observation Record = AVAILABLE
↓
transaction complete
↓
返回 OBSERVATION_AVAILABLE_TYPED_OUTCOME
```

若事务失败：

```text
Admission 可保持 retryable
Checkpoint 不成立
Page 不开放用户 recognition
```

### 12.3 Recognition 事务

用户选择 `CONFIRMED` 或 `SELF_NAMED`：

```text
IDB readwrite transaction
↓
重新读取 Current Observation Record
↓
重新读取 Growth Canonical Envelope
↓
校验：
checkpoint = AVAILABLE
lifecycle = CURRENT
reference / lineage revision 当前
identity / Reality / Pressure / Gravity 匹配
不存在已提交 Choice
当前用户动作明确
↓
checkpoint = RECOGNIZED
checkpointRevision + 1
写 recognition provenance
↓
transaction complete
↓
返回 OBSERVATION_RECOGNIZED_TYPED_OUTCOME
↓
Page 才能进入 Choice-ready presentation
```

冻结：

> UI 不得先进入 Choice Ready，再异步尝试保存 Checkpoint。

### 12.3.1 “Lineage 建立 + Recognized”是否同一事务

正式裁决：

```text
Reference 生成：
随新 Gravity Encounter 建立，只生成一次

Canonical Lineage 建立：
随 AVAILABLE transaction complete 成立

Recognition：
只能更新一个已经 Canonical AVAILABLE 的 Current lineage
```

因此正常生产链不是：

```text
用户点击认出
↓
临时创建 Lineage
↓
同时写 Recognized
```

而是：

```text
Typed Surface
↓
Canonical Lineage + AVAILABLE 原子建立
↓
用户才获得 Recognize 交互资格
↓
Recognized 原子更新
```

若 Recognition command 发现 Canonical Lineage 不存在：

```text
LINEAGE_NOT_ESTABLISHED
→ SAFE_WITHHELD / RETRY SURFACE ADMISSION
```

它不得在 Recognition command 中临时补建 Lineage。

这样保证：

- Lineage 建立与 AVAILABLE 不存在半事务；
- Recognized 写入、Recovery 确认与 Typed Outcome 属于同一 IDB transaction complete；
- UI 不会在 Canonical Lineage 尚未成立时进入 Choice Ready；
- Recognition 失败不会创建孤立 Lineage。

### 12.4 Choice 事务

```text
同一个 IDB readwrite transaction
↓
读取 Current Observation Record
读取 Growth Canonical Envelope
↓
校验：
checkpoint = RECOGNIZED
lifecycle = CURRENT
gravityObservationReferenceId 匹配
checkpointRevision 匹配
identity / provenance 匹配
不存在已提交 Choice
没有 Formation terminal conflict
↓
写 Choice Action Intention
标记 Observation = CONSUMED_BY_CHOICE
记录 choiceActionIntentionReferenceId
↓
transaction complete
↓
返回 Choice COMMITTED
```

这要求：

```text
Choice Action Intention Controller
```

不再只接受 Page 传来的 Reference 字符串。

它必须消费：

```text
Typed Recognized Observation Proof
```

并在事务内重新验证。

### 12.5 新 Encounter 替换

创建新 Current Record 前：

```text
读取现有 Current Observation Record
读取现有 Choice / Fact / Receipt
↓
只有旧 lifecycle 已终结或正式消费
才能替换
```

旧标签晚到时：

```text
recordId 相同
但 current observationReferenceId 已改变
↓
STALE_OBSERVATION_LINEAGE
↓
不得写入
```

- IDB unavailable；
- DB open blocked；
- versionchange；
- transaction abort；
- write unconfirmed；
- sessionStorage unavailable；
- Checkpoint corrupted；
- identity mismatch；
- Pressure mismatch；
- Admission expired；
- Page unload；
- old async outcome；
- Renderer unavailable；
- WebGL context lost。

任何失败不得：

- 进入 Choice Ready；
- 创建 Choice；
- 改变 Growth；
- 生成新 ID；
- 回退 Page boolean；
- 伪造 Recognized。

### M｜No Backfill

- V1 Admission；
- V1 Growth；
- 旧页面状态；
- 旧六维完成；

都不生成 Checkpoint。

已有 Choice / Fact / Receipt 仍正常恢复。

## 二十三、失败与降级

## 二十四、forward SAFE_WITHHELD 回滚方案

### 24.1 原则

普通 `git revert` 不得恢复：

- revision-derived Observation ID；
- Page-local Recognized Authority；
- Choice string-only 成功路径；
- 第二 Checkpoint Storage；
- 六维进度持久化。

### 24.2 Forward counter-commit 目标

```text
Checkpoint Mutation：
PAUSED

New Observation Recognition：
SAFE_WITHHELD

New Choice Commit requiring Observation：
SAFE_WITHHELD

Gravity Admission Recovery：
READ-ONLY / PRESERVED

Observation Continuity Store：
READ-ONLY / PRESERVED

Existing Choice / Fact / Eligibility / Receipt / Crystal：
READABLE / PRESERVED

Returning Body Imprint：
PRESERVED

Old Page Authority：
NOT RESTORED

Old revision-derived ID：
NOT RESTORED
```

### 24.3 Counter-commit file boundary

未来 Runtime 交付前必须准备一份独立 forward counter-commit，预计只修改：

```text
Gravity Observation Continuity Controller
Choice Action Intention boundary
Gravity resume presentation
SAFE_WITHHELD gates
```

不得：

- 降级 DB schema；
- 删除 Observation Store；
- 清除 records；
- 清除 Growth；
- 恢复 V1 writer；
- 恢复 Page boolean。

### 24.4 触发条件

出现任一情况立即应用：

- 同一 Gravity Encounter 出现两个 Observation Reference；
- 同一 Observation 出现两个 Choice lineage；
- 旧标签覆盖新 Encounter；
- Choice 不验证 Recognized Checkpoint；
- UI 在 transaction complete 前显示 Choice Ready；
- Checkpoint 允许 Direct URL 绕过 Admission；
- Identity / provenance 串写；
- Checkpoint 失败后 Page fallback；
- V1 被自动回填；
- 远程干净快照无法复验。

## 二十五、迁移风险

### 25.1 数据库版本升级

风险：

- 旧连接阻塞 V2；
- Acceptance / Harness 保持连接；
- 多标签同时 upgrade。

控制：

- `versionchange` 主动关闭；
- `blocked` typed outcome；
- 不显示成功；
- 可重试；
- 不删除 V1。

### 25.2 物理事务域命名

现有数据库名包含 `lived-growth`。

Checkpoint 属于 Growth 前的 Continuity。

短期接受：

> 物理共域用于事务真实性，不代表 Growth 语义所有权。

刀后黄灯：

```text
数据库命名与更广泛 Life Adventure Transaction Domain 的长期治理
```

不得在本次迁移中顺带重命名数据库。

### 25.3 Page 体验压缩

恢复 `RECOGNIZED` 后不应机械恢复最后一个动画帧。

Presentation 可以：

- 静态显示同一生命已认出；
- 简短过渡至 Choice；
- Reduced Motion 直接呈现；
- 不重复三次靠近。

但这属于后续 Visual Runtime。

### 25.4 六维旧路径

当前六维页面步骤仍参与 Choice formation snapshot。

本迁移只移除它的恢复权威。

它是否保留为体验结构，继续由后续 Phase 3 Experience 工程裁决。
