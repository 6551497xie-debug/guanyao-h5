# XINMAI Visual Life System Constitution V1.0

## XINMAI-VISUAL-LIFE-SYSTEM-CONSTITUTION-P0

### 文档状态

- 项目：XINMAI / 星脉之境
- 底层系统：GUANYAO Life Engine / 观爻生命引擎
- 模式：视觉生命系统架构冻结 + 现有资产审查
- 阶段：P0
- 性质：视觉最高规范
- 代码修改：无
- Runtime 修改：无
- 新增类型 / 服务 / Engine：无

本宪法用于约束 XINMAI 启动、Genesis、StarBeast、Reality、Gravity、AI Reflection、Choice、Crystal 与 Archive 的全部后续视觉施工。

它不新增世界模型，不修改生命来源，不替代既有产品协议，也不授权大规模 UI 重构。

## 一、审查结论

### 1.1 当前不是“缺少视觉”

当前工程已经具备一条真实可运行的视觉生命主干：

```text
同一深空星河
↓
同一生命核心
↓
28 宿生命坐标
↓
四象方向场
↓
力量节律
↓
同一星兽身体
↓
Reality 压力状态
↓
Gravity 惯性痕迹
↓
Choice 回应间隙
↓
Crystal 身体沉积
↓
Life Archive 时间记忆
```

当前最大问题不是能力缺失，而是：

1. 这些能力尚未被一份统一视觉宪法约束；
2. 七星生命经络仍只是可承载的内部结构，尚未成为有真实来源的正式视觉层；
3. 色彩、材质和节律分散在 Renderer、页面 CSS 与局部内联参数中；
4. 旧的仪器化、卡片化、旋转轨道视觉仍作为隔离资产或 fallback 风险存在；
5. 13 个生命阶段已经部分存在，但尚未统一遵守“上一屏结束帧就是下一屏开始帧”。

### 1.2 当前应采用的视觉母结构

XINMAI 的统一视觉不是一个组件库，而是一具持续存在的生命：

```text
星河空间 Space
↓
生命核心 Core
↓
七星经络 Meridian
↓
星兽生命 Presence
↓
Crystal 沉积 Imprint
```

五层不是五张叠加贴图。

它们分别回答：

| 层 | 回答的问题 |
| --- | --- |
| 星河空间 | 生命存在于哪里 |
| 生命核心 | 这个生命是谁 |
| 七星经络 | 力量如何在生命中流动 |
| 星兽生命 | 这个生命如何被看见 |
| Crystal 沉积 | 这个生命经历后留下了什么 |

### 1.3 最高判断

> XINMAI 的视觉不是装饰，也不是结果展示。视觉是生命状态语言。

用户不应通过报告知道自己发生了变化。

用户应先从同一生命的呼吸、结构、姿态、流动与纹理中看见变化，文字随后只负责确认。

## 二、视觉最高原则

### 原则 1｜视觉只显化，不创造生命

正式关系保持：

```text
生命来源
↓
视觉状态
↓
Renderer
↓
用户感知
```

视觉层不得：

- 重新计算二十八宿；
- 自行决定四象；
- 根据效果偏好生成新的星兽身份；
- 用 Crystal 反向改变初始生命身份；
- 从颜色、模型或贴图推断生命事实。

### 原则 2｜一个生命只有一个核心

生命核心代表用户持续存在的生命身份。

全链路必须保持：

- 同一空间锚点；
- 同一暖白象牙光温；
- 同一基础呼吸；
- 同一核心与身体关系。

阶段可以改变核心被看见的强弱、距离和响应，不得新增第二核心，不得让月亮、出生宿、压力点、Crystal 或星兽胸腔成为第二个“我”。

### 原则 3｜状态改变，身份不变

压力、惯性、Choice 与 Crystal 只能改变：

- 姿态；
- 呼吸；
- 密度；
- 流向；
- 局部纹理；
- 空间张力。

不得改变：

- 生命核心；
- 出生宿来源；
- 四象来源；
- 星兽身份；
- 身体基础拓扑。

冻结：

```text
同一生命
×
不同经历
=
不同状态
```

而不是：

```text
不同经历
→
替换一个新生命
```

### 原则 4｜每个可见物必须有来源

每一个点、线、光、粒子、形变与纹理都必须回答：

1. 它来自星河、核心、经络、身体还是经历？
2. 它为什么在这一刻出现？
3. 它是否会进入下一阶段？
4. 如果删除文字，用户是否仍能感受到因果？

不能回答来源的对象不得进入正式视觉。

### 原则 5｜生命行为优先于效果

正式视觉动词只有：

- 呼吸；
- 流动；
- 收束；
- 展开；
- 停顿；
- 恢复；
- 沉积。

禁止把以下效果误认为生命：

- 自动旋转；
- 环绕轨道；
- 扫描；
- 点火；
- 爆发；
- 技能释放；
- 循环展示；
- 加载动画。

### 原则 6｜天地大于角色

星河不是星兽的背景板。

星兽、核心、Reality 与 Crystal 都发生在同一片天地中。

正式构图优先级：

```text
天地空间
>
生命关系
>
当前状态
>
文字说明
>
操作控件
```

禁止角色海报化、中央徽章化、收藏卡化与科幻 HUD 化。

### 原则 7｜相邻阶段必须视觉守恒

每一屏结束时保留下来的对象，必须成为下一屏的输入。

冻结：

```text
上一屏完成帧
=
下一屏开始帧
```

下一屏只能增加新的生命关系，不能重新生成宇宙、核心、身体或身份。

### 原则 8｜前台简单，后台复杂

用户不应看见：

- Engine；
- Protocol；
- Source；
- Projection；
- Renderer；
- Schema；
- 状态码；
- 评分；
- 调试标签。

后台可以拥有复杂生命模型，前台只让用户感受到这一刻生命发生了什么。

## 三、统一空间与相机宪法

### 3.1 XINMAI 是 3D 生命空间

XINMAI 不是 2D 星盘。

正式空间由三层深度组成：

| 深度 | 内容 | 视觉职责 |
| --- | --- | --- |
| 远景 | 稀疏恒星、星云暗部、天地时间痕迹 | 建立宇宙尺度与安静秩序 |
| 中景 | 二十八宿关系、方向场、现实扰动 | 建立生命与天地的关系 |
| 近景 | 星沙、身体粒子、Crystal 纹理 | 建立生命可触感与经历厚度 |

深度必须通过视差、粒子尺寸、清晰度、遮挡与速度差表达，不能只靠模糊滤镜伪装。

### 3.2 相机不是展示机器

相机代表用户与生命共同存在的位置。

相机不得：

- 围绕星兽巡游；
- 自动旋转展示模型；
- 用大幅推拉制造角色登场；
- 在相邻阶段重置观看方向。

相机允许：

- 极慢靠近；
- 呼吸级距离变化；
- 为 Reality 留出共同朝向；
- 在 Recognition 后建立“共同面对天地”的侧向关系。

### 3.3 一个旅程只使用一条空间轴

Genesis 中建立的核心位置、出生宿方向与星兽朝向，进入 Reality 后必须继续存在。

Gravity、Choice、Crystal 与 Archive 只能在同一空间轴上加入：

- 压力偏向；
- 惯性路径；
- 回应间隙；
- 经历纹理；
- 时间深度。

## 四、五层视觉生命系统

## Layer 1｜星河空间层 Starfield Space

### 定义

星河是用户生命发生的天地场，不是装饰背景。

它回答：

> 我的生命存在于怎样的秩序中？

### 正式来源

- 同一不可变深空星点拓扑；
- 二十八宿真实坐标关系；
- 时间与镜头状态；
- 当前 Reality 空间扰动；
- 历史经历的极弱远景痕迹。

### 视觉组成

- 深空；
- 大面积留白；
- 远、中、近三层星尘；
- 二十八宿；
- 极弱时间运行痕迹；
- 不抢主体的远景天地光。

### 运动规则

- 星河运行应慢于生命呼吸；
- 运动体现秩序与视差，不体现“旋转星盘”；
- 二十八宿是空间锚点，不是环形加载器；
- Reality 扰动只能使局部空间发生偏移、压缩或流向变化。

### 连续性红线

- Launch、Genesis、Reality、Gravity、Archive 必须消费同一宇宙身份；
- 页面切换不得重新随机生成星点；
- 二十八宿不得在不同阶段改变拓扑；
- 出生宿必须是已有星河中的一个位置，不得新增高亮点冒充来源。

### 禁止

- 密集星图；
- 占星盘；
- 十二宫；
- 星座知识图；
- 科幻 HUD；
- 等距环形轨道；
- 快速旋转；
- 黑底贴一层星点。

### 当前工程结论

`lifeUniverseStarField.ts` 已提供 420 个稳定深空星点、统一投影、2D fallback 与核心身份，是本层直接继承的权威基础。

`genesisWebGLRendererCore.ts` 已使用相同拓扑建立 WebGL 三维空间。

`LaunchLab.tsx` 已复用相同星场来源，但仍保留大量页面内 Canvas 编排；后续只校准消费关系，不重新创造星河。

## Layer 2｜生命核心层 Life Core

### 定义

生命核心是所有用户生命连续性的中心。

它回答：

> 无论发生什么，谁仍然是我？

### 正式身份

当前权威值来自 `LIFE_UNIVERSE_CORE_IDENTITY`：

- 锚点：`x = 0.5 / y = 0.48`；
- 基础呼吸周期：`3s`；
- 呼吸幅度：`0.08`；
- 核心色：`#FFF7E4`；
- 光晕色：`#E8C88A`；
- 移动端核心半径：以 `24 / 390` 视口宽度为基准；
- 半径约束：`18–28px`。

这些值是生命身份，不是单屏装饰。

### 呼吸双层规则

必须区分：

1. **核心身份呼吸**
   - 基础周期保持 3 秒；
   - 表达“我仍然存在”。

2. **身体力量节律**
   - 可由既有 Life Archetype 以约 4.2–8.2 秒调制；
   - 表达“我的力量如何运行”。

禁止用外层力量节律替换核心身份呼吸。

### 视觉组成

- 暖白核心；
- 低亮表面；
- 柔和光晕；
- 与经络和身体之间的传导；
- Recognition、Pressure、Recovery 时的微弱响应。

### 状态规则

| 状态 | 核心变化 | 核心不变 |
| --- | --- | --- |
| 等待 | 低频可见 | 位置、色温 |
| 时间进入 | 光质变得可读 | 身份 |
| 认出 | 一次吸气、轻微靠近 | 不新增主体 |
| 压力 | 稳定但外层收束 | 不熄灭 |
| Choice | 保持，允许一次停顿 | 不变色表示“正确” |
| Crystal | 一点回应 | 不被 Crystal 覆盖 |

### 禁止

- 第二暖白核心；
- 能量球技能感；
- 太阳/月亮替代用户身份；
- 核心爆发；
- 压力下熄灭；
- Crystal 成为新核心。

### 当前工程结论

本层已是当前最稳定的视觉资产，应直接继承，不重新设计。

## Layer 3｜七星生命经络层 Seven-Star Meridian

### 定义

七星生命经络是生命力量在身体内部流动的通道。

它回答：

> 我的生命力量正在何处流动，何处收束，何处恢复？

### 与其他结构的边界

七星经络不是：

- 星座连线；
- 骨骼；
- PCB 线路；
- 能力面板；
- 七项评分；
- 六维的重命名。

关系冻结：

```text
七星经络
=
内部生命流动

六维显影
=
现实影响被观察的六个窗口
```

两者不得互相冒充。

### 七星角色

| 星穴 | 生命职责 | 允许的视觉表达 |
| --- | --- | --- |
| 天枢 | 行动之轴 | 启动、向前传导 |
| 天璇 | 承载之轴 | 容纳、恢复、回弹 |
| 天玑 | 价值之轴 | 核心认可、内在稳定 |
| 天权 | 边界之轴 | 收束、决断、保护 |
| 玉衡 | 丰盛之轴 | 资源交换、流动 |
| 开阳 | 连接之轴 | 关系传导、信任 |
| 瑶光 | 本心之轴 | 真实、觉察、自我定义 |

### 视觉材料

- 星粉，不是线框；
- 深水中的微光，不是电路；
- 星穴，不是按钮；
- 呼吸传导，不是扫描；
- 局部滞涩与恢复，不是红绿状态灯。

### 状态语法

允许：

- 通畅；
- 变慢；
- 收束；
- 冻结；
- 旁路；
- 复流；
- 留痕。

禁止：

- 断裂惩罚；
- 红色报警；
- 百分比；
- 强弱排名；
- “升级经络”。

### 真实来源边界

当前工程尚无可追溯的七星经络 Runtime 状态。

现有 `genesisWebGLRendererCore.ts` 中的 stellar skeleton、身体节点与星沙传导只能被认定为：

> 七星经络的可复用视觉承载面。

它们不能在没有真实投影时被前台命名为天枢、天璇、天玑、天权、玉衡、开阳、瑶光，也不能从六维或压力字段推断七星结果。

后续施工必须先消费已有正式来源；如果来源仍不存在，只允许表现匿名的内部生命流动，不允许伪造七星状态。

### 当前工程结论

本层是五层系统中最大的正式缺口：

- 拥有身体拓扑；
- 拥有流动能力；
- 缺少真实七星状态来源；
- 缺少统一的星穴视觉语法。

因此下一阶段应先做视觉消费边界，不应新建评分系统。

## Layer 4｜星兽生命层 StarBeast Presence

### 定义

星兽是用户本我生命力量被看见后的持续存在。

它回答：

> 我的生命力量如何成为一个可以与我同行的存在？

### 组成关系

```text
生命核心
+
出生宿生命种子
+
四象方向场
+
力量运行节律
+
星沙身体
=
星兽生命存在
```

星兽不是四象动物，不是母码图标，也不是单独生成的角色模型。

### 双层结构

#### 内层：生命本体

- 同一核心；
- 同一内部拓扑；
- 同一出生记忆；
- 同一力量节律；
- 同一生命身份。

#### 外层：生命显相

- 姿态；
- 重心；
- 朝向；
- 开合；
- 密度；
- 星沙表皮；
- 四象方向性。

外层可以变化，内层身份必须保持。

### 三态模型

| 状态 | 含义 | 视觉语言 |
| --- | --- | --- |
| 本源态 Essence | 生命自然流动 | 稳定、舒展、通畅 |
| 遮蔽态 Veil | 生命为适应现实而保护自己 | 收束、紧绷、偏移、沉潜 |
| 流生态 Flow | 用户产生新的回应 | 复流、重新平衡、带痕恢复 |

三态必须是同一身体的状态变化，不得替换模型。

### Presence 四步节律

```text
安静存在
↓
感知世界
↓
回应世界
↓
恢复自身
```

恢复不是回到播放前的初始帧，而是进入带有经历痕迹的新稳态。

### 空间关系

星兽不得正面居中等待被欣赏。

优先：

- 三分之一偏置；
- 侧向姿态；
- 与用户共同朝向天地；
- 有前后距离；
- 有稳定站位或承载位置。

陪伴不是盯着用户，而是与用户一起面对世界。

### 禁止

- 宠物动作；
- 大眼睛；
- 拟人表情；
- 游戏待机；
- 角色登场；
- 模型替换；
- 技能形态；
- 四象换皮；
- 星兽覆盖核心。

### 当前工程结论

`genesisWebGLRendererCore.ts` 已经具备：

- 同一 stellar skeleton；
- 星沙身体；
- 四象方向场；
- Life Archetype 外层节律；
- Recognition 回应；
- Pressure / Recovery 状态；
- Crystal 身体沉积。

该 Renderer 是星兽生命层的生产主干，应继承其身份连续性；后续重点是收束视觉语义和解耦阶段参数，不是另造新模型。

## Layer 5｜Crystal 沉积层 Crystal Imprint

### 定义

Crystal 是生命经历被理解、被回应后留下的智慧纹理。

它回答：

> 这次经历在同一个生命里留下了什么？

### 来源连续性

Crystal 必须来自刚刚发生变化的位置：

```text
现实影响某处生命
↓
该处发生收束 / 冻结 / 偏移
↓
用户产生新的回应
↓
该处恢复流动
↓
该处留下微小纹理
```

禁止在生命身体旁边生成独立收藏品。

### 身体连续性

Crystal 可以：

- 成为身体纹理；
- 沿核心到变化位置形成一次低亮路径；
- 进入星河时间深度；
- 沉积进人格年轮。

Crystal 不可以：

- 独立悬浮为第二主体；
- 变成卡片奖励；
- 显示等级、数量、稀有度；
- 触发庆祝爆发。

### 情绪规则

Crystal 出现时：

- 声音：一声；
- 光：一点；
- 动作：一次沉积；
- 留白：大于说明；
- 情绪：理解，不是胜利。

### 时间规则

```text
当前身体纹理
↓
离开当前 Reality
↓
成为生命记忆
↓
```

## 六、统一材质系统

材质不是美术皮肤，而是生命状态的触感。

| 材质 | 生命语义 | 主要层 | 动态 |
| --- | --- | --- | --- |
| 星沙 | 生命由天地物质组成 | 星河、星兽身体 | 缓慢聚散、沿结构附着 |
| 琉璃 | 生命内部可透见但不可完全解释 | 核心、身体内腔 | 光在内部通过，不做镜面炫光 |

- 水墨不能变成国风贴图。

同一材质在不同阶段只能改变密度、透明度、流速与局部结构，不得替换生命身份。

## 七、统一动态系统

### 7.1 动态分层

| 动态层 | 建议节律 | 作用 |
| --- | --- | --- |
| 核心身份呼吸 | 3s 基础周期 | 确认“我仍然存在” |
| 身体力量节律 | 4.2–8.2s 既有原型区间 | 表达力量运行方式 |
| 四象方向呼吸 | 6.4s 既有方向场基准 | 表达天地来源 |
| 星河环境运行 | 8–18s 以上的低幅变化 | 表达天地秩序 |
| Recognition 回应 | 约 1.25s，前置安静约 1.85s | 建立关系 |
| Reality 进入 | 1.6s 身份保持，约 4.6s 稳定 | 保持同行连续 |
| Choice 停顿 | 约 3.6s 觉察区间 | 让旧反应不再自动接管 |
| Crystal 沉积 | 约 1.65–3.4s 一次性完成 | 留下经历，不庆祝 |
| 长期记忆呼吸 | 8–12s 极弱变化 | 表达“它记得” |

以上为当前工程审查得到的区间，不是要求所有动画统一时长。

### 7.2 五个正式动态阶段

#### 呼吸 Breath

用于核心与身体稳态。

要求：

- 不像呼吸灯；
- 不通过亮灭表达生命；
- 幅度小于关系和状态变化。

#### 流动 Flow

用于星沙、经络、方向场。

要求：

- 有来源和去向；
- 不形成固定轨道；
- 不机械循环。

#### 收束 Contract

用于 Pressure、Veil、Gravity。

要求：

- 发生在同一身体；
- 核心仍可见；
- 表达保护，不表达失败。

#### 展开 Expand

用于 Life Force、Recognition、Choice、Recovery。

要求：

- 不是爆发；
- 不是升级；
- 展开后进入新稳态。

#### 沉积 Deposit

用于 Crystal 与 Archive。

要求：

- 一次发生；
- 来源位置明确；
- 留下微小可持续纹理；
- 不反复庆祝。

### 7.3 动态禁止

- 自动公转；
- 模型自转；
- 无因果粒子喷发；
- 技能释放；
- UI loading spinner；
- 频繁闪烁；
- 无限循环的奖励呼吸；
- 页面进入即表演完整动画；
- 通过动画掩盖来源缺失。

### 7.4 Reduced Motion

减少动态时不能删除生命关系。

应保留：

- 同一空间；
- 同一核心；
- 状态前后差异；
- Crystal 来源和位置；
- 文字确认。

只移除持续位移、复杂视差与高频粒子。

### 9.3 `genesisWebGLRendererCore` 详细判断

#### 需要升级

1. Renderer 体量较大，多个阶段参数集中在同一实现中；

5. 色彩与材质常量分散；

```text

再收束参数和材质
↓
最后减少隐性 DOM 耦合
```

施工方向：

`LifeUniverseRouteFallback` 使用旋转二十八宿环。

风险：

加载阶段重新把生命宇宙变成占星盘。

施工方向：

- 保留 2D fallback；
- 使用同一稳定空间投影；
- 取消自动轨道；
- 保持核心和出生宿关系。

### P1｜Gravity 多阶段视觉层级过密

同一页面承载六维、Gravity、Choice、Crystal。

用户感到进入多个功能模块，而不是同一生命发生连续变化。

施工方向：

- 不拆新路由；
- 按逻辑 Screen 冻结单一视觉任务；

### P2｜历史记忆仍有叠加层感

Reality 与 Home 的历史/Crystal 纹理部分由 SVG 覆盖 WebGL。

风险：

生命记忆像 UI 贴图，而不是身体经历。

施工方向：

- 先统一几何和材质；
- 再评估是否进入 Renderer；
