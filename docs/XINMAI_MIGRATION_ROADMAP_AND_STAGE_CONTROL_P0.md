# XINMAI MIGRATION ROADMAP AND STAGE CONTROL P0

## 文档定位

- 项目：XINMAI / 星脉之境
- 底层系统：GUANYAO Life Engine / 观爻生命引擎
- 文档编号：`XINMAI-MIGRATION-ROADMAP-AND-STAGE-CONTROL-P0`
- 模式：XINMAI 产品迁移路线与阶段控制协议
- 状态：`PRODUCT ROADMAP GOVERNANCE FREEZE`
- 生效日期：`2026-07-27`
- 工程影响：无

本协议用于管理 XINMAI 从“生命觉察工具”迁移为“东方生命游戏世界”的阶段路线、阶段门禁、主线锁定与跨阶段施工秩序。

本协议：

- 只新增产品架构管理文档；
- 不修改代码；
- 不新增 Engine、类型、服务或数据结构；
- 不改变现有 Runtime；
- 不重新定义既有生命身份与成长链路；
- 不授权任何具体功能施工；
- 不以新路线否定已有资产；
- 不替代 Product Control Tower 与 Migration & Construction Rhythm；
- 负责回答“迁移通过之后，按什么阶段前进”。

- `XINMAI Product Control Tower P0`；
- `XINMAI Product Migration & Construction Rhythm P0`；
- GUANYAO Life Engine；
- Game Experience Reset；
- Life Origin；
- 二十八宿生命身份；
- StarBeast；
- First Encounter；

- Reality；
- Pressure Seed；
- Six Dimension；
- Gravity；
- Inner View；
- Choice；
- Crystal；
- Archive 与生命圣所方向。

当前治理体系已经回答：

### Product Control Tower

回答：

> 做什么、为什么做、什么时候做。

### Migration & Construction Rhythm

回答：

> 使用什么刀、如何施工、何时停止。

### 本协议

回答：

> 迁移被批准之后，先完成哪个阶段、每个阶段如何通过、什么时候允许进入下一阶段。

当前缺失不是方向，也不是功能。

当前缺失是：

```text
迁移方向成立
↓
多个阶段同时拥有既有资产
↓
资产存在被误认为阶段完成
↓
多个系统同时深化
↓
当前主线失焦
↓
相邻阶段互相覆盖
↓
进入无限循环优化
```

因此建立：

# XINMAI Migration Roadmap & Stage Control

它不是新产品模块。

它是：

> XINMAI 大型产品迁移的时间秩序与阶段门禁。

## 二、三份治理协议的分工

三份治理协议共同组成 XINMAI 产品工程总控。

```text
Product Control Tower
决定问题归属与版本优先级
↓
Migration & Construction Rhythm
决定迁移刀 / 大刀 / 精修刀及施工方法
↓
Migration Roadmap & Stage Control
决定阶段顺序、进入条件与退出条件
↓
具体产品施工
```

### 2.1 Product Control Tower 不被替代

本协议不重新判断：

- 一个建议是否属于当前主线；
- 一个问题应 NOW、MAP、DEFER 还是 REJECT；
- 一个能力属于哪一产品层；
- 一项施工是否值得开始。

这些继续由 Product Control Tower 负责。

### 2.2 Construction Rhythm 不被替代

本协议不重新定义：

- Migration Blade；
- Major Blade；
- Refinement Blade；
- Migration Audit；
- Construction State Card；
- 六项施工反馈；
- Runtime 证据等级。

这些继续由 Migration & Construction Rhythm 负责。

### 2.3 本协议新增的唯一治理能力

本协议新增：

- Phase 路线；
- Phase 主线锁；
- Phase 入口门禁；
- Phase 出口门禁；
- 跨 Phase 消费者检查；
- 阶段回退规则；
- 阶段资产冻结；
- 阶段完成证据；
- 当前迁移窗口。

## 三、迁移最高原则

冻结：

> XINMAI 的迁移不是一次重做，而是在保护已有生命资产基础上的逐层进化。

禁止：

- 推翻式重构；
- 全量替换已有 Runtime；
- 因新范式成立而否定旧资产；
- 多个 Phase 同时成为施工主线；
- 用功能存在证明阶段完成；
- 以后续阶段的完整度掩盖前序关系缺失；
- 用未来系统倒逼当前主线改变；
- 为追求视觉统一删除已成立的生命因果。

迁移采用：

```text
保留
↓
连接
↓
增强
↓
扩展
```

### 3.1 保留 Preserve

保留已经成立的：

- 产品宪法；
- 用户因果；
- Runtime；
- 数据来源；
- 视觉资产；
- 身份连续性；
- 关系痕迹；
- 成长记录。

### 3.2 连接 Connect

先让既有资产进入同一用户链路。

例如：

```text
Life Whisper
↓
既有 Pressure Seed
```

而不是：

```text
Life Whisper
↓
新建第二套现实理解系统
```

### 3.3 增强 Enhance

只有在消费者关系成立后，才增强：

- 存在感；
- 互动反馈；
- 生命语言；
- 阶段连续；
- 用户参与。

### 3.4 扩展 Extend

只有当前阶段通过后，才扩展：

- 深层经络；
- Crystal 生态；
- Life Weather；
- 声音星轨；
- Sanctuary。

## 四、当前核心迁移

当前核心迁移冻结为：

```text
生命觉察工具
↓
东方生命游戏世界
```

这不是增加：

- 游戏皮肤；
- 任务；
- 积分；
- 等级；
- 战斗；
- 收集系统。

而是重新定义用户与产品的关系。

### 4.1 旧关系

```text
用户
↓
输入问题
↓
系统分析
↓
获得反馈
↓
离开
```

旧关系中的产品是工具。

用户是被分析对象。

### 4.2 新关系

```text
玩家
↓
进入生命世界
↓
发现生命伙伴
↓
主动互动
↓
共同经历现实
↓
产生新的回应
↓
留下生命痕迹
↓
回到持续生长的生命宇宙
```

新关系中的产品是生命世界。

用户是生命探索者。

### 4.3 迁移判断标准

迁移是否发生，不看：

- 页面是否更像游戏；
- 动效是否更多；
- 星兽是否更具象；
- 功能是否更丰富。

而看：

1. 用户是否进入一个持续存在的世界；
2. 用户是否认出具体生命身份；
3. 用户是否与生命建立关系；
4. 用户的现实是否进入世界；
5. 用户是否产生主动回应；
6. 经历是否留下长期痕迹。

## 五、阶段编号规则

本路线采用：

```text
Phase 0
世界基座

+

Phase 1—5
五个产品迁移阶段
```

因此：

- Phase 0 是所有迁移的空间前提；
- Phase 1–5 是五个依次推进的产品关系阶段；
- “五阶段迁移路线”不包含 Phase 0 基座；
- Phase 数量不等于页面数量；
- 一个 Phase 可以消费多个页面；
- 一个页面不得同时承担多个 Phase 的完整责任。

### 5.1 Phase 与 Layer 不是同一个概念

Layer 回答：

> 这个能力属于产品的哪一层。

Phase 回答：

> 这个能力在迁移时间线上什么时候成为主线。

同一 Layer 可以跨多个 Phase 被消费。

同一 Phase 也可以消费多个 Layer。

禁止：

- 把 Layer 2 直接等同于 Phase 2；
- 因某 Layer 已有代码而宣布对应 Phase 完成；
- 用空间层的精修替代关系阶段施工。

## 六、Phase 0｜生命世界基础 World Foundation

### 6.1 阶段问题

回答：

> 用户进入的是不是一个真实存在的生命世界。

### 6.2 阶段目标

让用户相信：

> 这里不是一张背景，也不是一个界面，而是一片持续存在的生命天地。

### 6.3 包含能力

- 黑曜星河；
- 动态景深；
- 天地场；
- 星尘空间；
- 时间感；
- 音景；
- 东方留白；
- 页面空间连续；
- 同一生命核心所在的空间基础。

### 6.4 核心体验

```text
现实噪音
↓
空间减速
↓
进入黑曜星河
↓
感知天地尺度
↓
相信世界存在
```

### 6.5 必须保护资产

- 动态星河景深；
- 星尘层次；
- 黑曜空间；
- 东方简素；
- 星脉微光；
- 天地大于角色；
- 移动端稳定体验。

### 6.6 禁止

- 为突出星兽破坏天地尺度；
- 将星河压缩为角色背景；
- 用密集星点替代景深；
- 引入科幻 HUD；
- 每屏重建不同宇宙；
- 让启动体验变成加载动画；
- 以视觉炫技证明世界存在。

### 6.7 Phase 0 Definition of Done

必须同时成立：

1. 隐藏解释文字，用户仍感到进入一个空间；
2. 空间具有前后、远近、时间与呼吸；
3. 不出现工具首页或加载页感；
4. 后续生命主体可以自然存在于其中；
5. 世界资产能被 Genesis、Reality 与回归入口连续消费。

验收句：

> 我进入了一个一直存在的生命世界。

### 6.8 阶段控制

Phase 0 是基座，不因通过而停止维护。

但通过后：

- 只允许保护性维护；
- 允许阻断性修复；
- 允许服务当前 Phase 的最小增强；
- 不再独立成为视觉探索主线。

## 七、Phase 1｜生命身份建立 Identity Formation

### 7.1 阶段问题

回答：

> 这是谁。

### 7.2 阶段目标

让用户认出：

> 这是一个有天地来源、属于我的具体生命。

### 7.3 包含能力

- 生命钥匙；
- 出生来源；
- 生命坐标；
- 二十八宿天地场；
- 本命宿骨相；
- 四象力量家族；
- 星兽原相；
- 天地之名；
- 可选用户之名；
- 生命身份恢复；
- 新老用户身份连续。

### 7.4 核心体验

```text
出生钥匙
↓
天地回应
↓
本命宿群显现
↓
星兽原相被看见
↓
用户认出生命身份
```

### 7.5 不是

- 系统分配角色；
- 人格测试结果；
- 命理报告；
- 四象属性卡；
- 星兽召唤；
- 宠物领取；
- 用户随机选择角色。

### 7.6 用户必须知道

无需理解所有后台概念，但用户应能感知：

1. 这个生命有来源；
2. 这些星的位置有意义；
3. 它不是通用形象；
4. 它与我的出生生命坐标相关；
5. 它不是刚被生成，而是刚被我认出。

### 7.7 Phase 1 Definition of Done

必须同时成立：

1. 用户无需长文案即可看见生命主体；
2. 用户知道这是自己的本命生命；
3. 本命宿、四象与星兽形成单一身份链；
4. 星兽具备身体方向、核心与呼吸；
5. 不依赖角色卡解释身份；
6. 老用户回来仍恢复同一生命；
7. 当前状态不会覆盖身份。

验收句：

> 原来这就是属于我的生命。

### 7.8 Phase 1 出口资产

Phase 1 必须向 Phase 2 交付：

```text
同一生命身份
+
可被触碰的生命主体
+
可恢复的本命来源
+
稳定的身体与核心
```

如果 Phase 2 需要重新生成主体，Phase 1 未完成。

## 八、Phase 2｜生命关系建立 Relationship Formation

### 8.1 阶段问题

回答：

> 我和它如何产生关系。

### 8.2 阶段目标

让用户从观看者变成参与者。

用户感知：

> 它听见了我，而我愿意继续靠近它。

### 8.3 包含能力

- First Encounter；
- 用户触碰；
- 星兽回应；
- Life Whisper；
- 可选命名；
- 认出；
- 同行；
- 老用户回归回应；
- 关系后的新稳态。

### 8.4 核心循环

```text
用户靠近
↓
生命回应
↓
用户表达
↓
生命再次回应
↓
关系成立
```

### 8.5 Life Whisper 在本阶段的责任

Life Whisper 首先承担：

> 用户向自己的生命留下一句真实表达。

它不是：

- AI 对话入口；
- 心理咨询输入框；
- Reality 分析表单；
- 自动尘遮识别；
- 第二套 Pressure Seed。

它在 Phase 2 的直接输出是：

- 关系发生；
- 生命听见；
- 星兽产生克制回应；
- 用户愿意同行。

它向 Phase 3 的桥梁输出是：

> 一条可被既有 Pressure Seed 消费的用户原始表达。

### 8.6 命名规则

命名是关系动作，不是身份计算。

```text
天地之名
提供来源

+

用户之名
提供关系
```

命名：

- 可选；
- 不阻断同行；
- 不替代二十八宿；
- 不改变生命身份；
- 不创建第二个角色。

### 8.7 Phase 2 Definition of Done

必须同时成立：

1. 用户至少完成一次主动动作；
2. 星兽对该动作产生明确但克制的回应；
3. 回应来自同一身体与核心；
4. 用户表达不立即变成分析报告；
5. 关系成立后进入新稳态，而非恢复原帧；
6. 用户愿意带着它进入 Reality；
7. 老用户回来不是重新相遇，而是继续关系。

验收句：

> 我不是看见了一个形象，我和它建立了关系。

### 8.8 Phase 2 出口资产

Phase 2 必须向 Phase 3 交付：

```text
同一生命伙伴
+
已成立的同行关系
+
用户原始表达
+
生命回应后的状态
```

如果进入 Reality 时用户感觉“系统开始分析我”，Phase 2 到 Phase 3 的桥梁未通过。

## 九、Phase 3｜现实生命冒险 Reality Adventure

### 9.1 阶段问题

回答：

> 这个生命如何与我共同面对现实。

### 9.2 阶段目标

让现实进入生命世界，而不是让用户离开生命世界去使用分析工具。

### 9.3 包含能力

- Reality Event；
- Pressure Seed；
- Six Dimension Life Observation；
- StarBeast State；
- Gravity；
- AI Reflection；
- Inner View；
- 当前生命状态；
- 过去痕迹与当前现实的边界。

### 9.4 核心循环

```text
现实靠近
↓
同一生命产生回应
↓
用户观察
↓
Pressure Seed 形成候选理解
↓
六维留下生命痕迹
↓
Gravity 显示重复保护方式
↓
AI 帮助用户照见
```

### 9.5 Pressure Seed 保护规则

Pressure Seed 继续作为已有现实理解资产。

禁止：

- 新增第二套压力理解系统；
- 让 Life Whisper 直接生成星兽最终状态；
- 把候选 Pressure Seed 当作用户事实；
- 前台暴露工程字段；
- 把压力种子显示为人格标签。

### 9.6 Reality 的入口门禁

Reality 只有在以下条件成立时才可成为主线：

1. 同一生命身份已稳定；
2. 星兽关系已经成立；
3. Life Whisper 或现实事件拥有明确来源；
4. Reality 能延续同一空间与核心；
5. 用户不会被重新定义为分析对象。

### 9.7 Phase 3 Definition of Done

必须同时成立：

1. 用户能把一段真实经历带入生命世界；
2. 星兽在压力中仍保持身份可见；
3. Pressure Seed 是开放候选而非结论；
4. 六维表达痕迹而非评分；
5. Gravity 表达保护方式而非缺陷；
6. AI 先镜像、再命名、再理解、再邀请转化；
7. 用户感到“我和它共同经历”，而非“系统完成分析”。

验收句：

> 现实进入了我的生命世界，而它仍陪我一起面对。

### 9.8 Phase 3 出口资产

Phase 3 必须向 Phase 4 交付：

```text
被用户确认的现实经历
+
被理解的保护方式
+
保持连续的生命状态
+
可能产生新回应的觉察空间
```

如果没有觉察空间，Choice 不得提前出现。

## 十、Phase 4｜生命成长沉积 Growth & Memory

### 10.1 阶段问题

回答：

> 我的回应如何成为生命的一部分。

### 10.2 阶段目标

让一次真实的新回应留下克制、连续、可追溯的生命印记。

### 10.3 包含能力

- Choice；
- 恢复后的新稳态；
- Crystal；
- Personality Ring；
- Archive；
- 生命章节；
- 经历痕迹；
- 成长记忆。

### 10.4 核心循环

```text
旧回应出现
↓
觉察空间形成
↓
用户产生新的回应
↓
生命重新稳定
↓
经历留下纹理
↓
Crystal 沉积
↓
进入生命年轮
```

### 10.5 Choice 规则

Choice 不是独立任务页面。

Choice 是：

> 生命连续过程中主动权重新出现的自然事件。

禁止：

- 正确答案；
- 任务完成；
- 道德判断；
- 奖励按钮；
- 强迫转变；
- AI 替用户选择。

### 10.6 Crystal 规则

Crystal 不是：

- 奖励；
- 装备；
- 收藏掉落；
- 数值成长；
- 胜利证明。

Crystal 是：

> 被理解、被回应、被生命吸收的一段经历。

Crystal 必须：

- 来自刚刚发生变化的位置；
- 与星兽身体连续；
- 与生命经络或纹理连续；
- 进入年轮；
- 保留来源；
- 情绪克制。

### 10.7 Phase 4 Definition of Done

必须同时成立：

1. Choice 来自已形成的觉察空间；
2. 用户保有不改变的权利；
3. 新回应改变关系而非完成任务；
4. 恢复不是回到初始帧；
5. 身体保留经历后的微小变化；

## 十三、阶段切换总规则

冻结：

> 未完成前一阶段核心用户结果，不进入下一阶段深挖。

### 13.1 阶段通过不等于功能存在

- Reality Runtime 存在，不代表 Phase 3 已通过；
- Crystal 组件存在，不代表 Phase 4 已通过；
- Archive 页面存在，不代表 Phase 5 已通过；
- 星兽 Renderer 存在，不代表 Phase 1 已通过。

阶段通过只看：

> 用户关系结果是否成立。

### 13.2 正确顺序

```text
生命世界
↓
生命身份
↓
生命关系
↓
现实冒险
↓
成长沉积
↓
长期宇宙
```

### 13.3 错误顺序

```text
星兽关系尚未成立
↓

```

```text
用户尚未认出生命身份
↓
深化七星内观
```

```text

↓
增加更多 AI 解释
```

```text
Archive 尚未表达生命连续
↓
扩展声音收藏
```

### 13.4 相邻阶段最小桥梁

允许为验证前一阶段出口，施工下一阶段的最小桥梁。

例如：

- Phase 2 可验证 Life Whisper 是否能交给 Pressure Seed；
- Phase 1 可验证认出后是否保持同一星兽进入关系；
- Phase 3 可验证理解后是否自然产生回应空间。

但最小桥梁不得：

- 变成下一阶段完整施工；
- 引入下一阶段深层系统；
- 反向修改前一阶段身份；
- 成为绕过阶段门禁的理由。

## 十六、阶段状态定义

每个 Phase 只能处于以下一种状态。

### LOCKED

前序门禁未通过。

不得施工。

### MAPPED

完成只读资产映射。

尚未进入施工。

### ACTIVE

当前主线。

允许按批准范围施工。

### VALIDATING

核心能力已经施工，正在真实体验验收。

禁止同时继续扩张范围。

### PASSED

Definition of Done 已通过。

资产进入保护清单。

### MAINTENANCE

仅做阻断性修复与必要精修。

不再成为独立探索主线。

### DEFERRED

能力有价值，但不属于当前阶段。

进入后续路线。

## 十七、单主线与迁移窗口

冻结：

> 一个时刻只能有一个产品主线，但可以存在一个相邻阶段验证窗口。

### 17.1 单主线

主线决定：

- 当前最重要的用户问题；
- 当前可接受的施工范围；
- 当前验收句；
- 当前停止条件。

### 17.2 相邻验证窗口

相邻验证窗口只用于：

- 验证阶段出口能否被下一阶段消费；
- 发现桥梁缺失；
- 验证连续性；
- 做只读 MAP；
- 实现最小可逆桥梁。

它不能：

- 成为第二条主线；
- 扩展下一 Phase；
- 提前施工未来生态；
- 转移当前验收注意力。

### 17.3 当前迁移窗口

当前 A 级主线窗口：

```text
Phase 1
生命身份建立
↓
Phase 2
生命关系建立
```

二者不是无序并行。

依赖关系：

```text
Phase 1 提供同一生命身份
↓
Phase 2 消费该身份建立关系
```

当前执行方式：

- Phase 1：身份稳定与可认出；
- Phase 2：关系闭环验证；
- Phase 3：只允许最小消费者 MAP；
- Phase 4：DEFER；
- Phase 5：DEFER。

## 二十四、阶段回退与异常处理

### 24.1 何时允许回退

只有发现以下情况时，允许回到前序 Phase：

- 前序用户结果从未真实通过；
- 当前施工暴露身份不连续；
- 当前消费者需要不存在的输入；
- 已有资产被错误标记为阶段完成；
- 真实用户无法理解核心关系；
- 当前 Phase 必须依赖第二套系统才能成立。

### 24.2 回退不是重做

回退流程：

```text
冻结当前扩展
↓
定位前序缺口
↓
保护已有资产
↓
修复最小因果
↓
重新验证出口门禁
↓
恢复当前阶段
```

禁止：

- 推翻整个 Runtime；
- 顺便重做视觉系统；
- 扩大修复范围；
- 用回退重新开启无限探索；
- 删除后续已有资产。

### 24.3 阶段异常分类

#### Identity Gap

用户不知道星兽属于自己。

回到 Phase 1。

#### Relationship Gap

用户只能观看，无法产生关系。

回到 Phase 2。

#### Continuity Gap

进入 Reality 后像进入另一个工具。

修复 Phase 2 → Phase 3 桥梁。

#### Growth Causality Gap

Crystal 与刚刚的回应无来源关系。

修复 Phase 3 → Phase 4 桥梁。

#### Sanctuary Memory Gap

回归后过去覆盖当前，或世界不记得用户。

修复 Phase 4 → Phase 5 桥梁。

```text
验证下一阶段最小消费
```

### 25.1 MAP

确认：

- 已有 Runtime；
- 页面消费者；
- 数据来源；
- 视觉资产；
- 缺失桥梁；
- 重复建模风险。

### 25.2 LOCK

冻结：

- 阶段目标；
- 当前刀型；
- 输入；
- 输出；
- 消费者；
- 禁止范围；
- Definition of Done。

### 25.3 BUILD

只构建：

> 让本阶段用户结果成立的最小完整能力。

### 25.4 VALIDATE

验证：

- 真实进入；
- 真实动作；
- 真实状态；
- 前后连续；
- 无文字情况下的用户感知；
- 移动端体验；
- 既有资产未被覆盖。

### 25.5 PASS

只有出口门禁通过，才标记 PASS。

### 25.6 PROTECT

将阶段资产加入保护清单。

### 25.7 BRIDGE

只验证下一阶段能否消费输出。

不提前扩展下一阶段。

## 二十六、每阶段允许的刀型

### 26.1 MAPPED 阶段

允许：

- 只读审查；
- Migration Audit；
- 数据消费映射；
- 风险报告；
- 协议沉淀。

禁止：

- 大规模代码施工；
- 视觉精修；
- 新系统实现。

### 26.2 ACTIVE 阶段

允许：

- 当前阶段 Major Blade；
- 阻断性 Refinement Blade；
- 必要的相邻桥梁；
- 已批准 Migration Blade。

### 26.3 VALIDATING 阶段

允许：

- 验收修复；
- 节奏校准；
- 性能修复；
- 可访问性修复；
- 不改变因果的精修。

禁止：

- 新增范围；
- 新概念；
- 新消费者；
- 同时启动下一大刀。

### 26.4 PASSED / MAINTENANCE 阶段

允许：

- 回归修复；
- 资产保护；
- 当前 Phase 必需的兼容；
- 无因果变化的性能优化。

禁止：

- 再次成为视觉探索主线；
- 为局部偏好推翻完成标准；
- 无止境打磨。

## 二十七、问题处理决策

所有新问题必须经过：

```text
问题出现
↓
归属 Layer
↓
归属 Phase
↓
判断是否阻断当前阶段
↓
判断是否影响阶段出口
↓
检查已有消费者
↓
NOW / MAP / DEFER / REJECT
```

### NOW

满足：

- 阻断当前阶段目标；
- 属于当前 Phase；
- 消费者明确；
- 已有资产可承载；
- DoD 清晰。

### MAP

满足：

- 可能连接当前与下一 Phase；
- Runtime 状态不清；
- 消费者关系不清；
- 暂不授权施工。

### DEFER

满足：

- 有价值；
- 不阻断当前阶段；
- 属于后续 Phase；
- 现在施工会分散主线。

### REJECT

满足：

- 违反产品宪法；
- 创建重复系统；
- 破坏阶段因果；
- 将用户重新变成分析对象；
- 将成长奖励化；
- 无消费者；
- 只有视觉或文字增加，没有关系价值。

## 三十一、无效阶段推进否决规则

以下情况不能被视为阶段推进：

1. 新增页面，但用户关系未变化；
2. 新增文案，但用户仍依赖解释；
3. 新增动画，但生命没有回应用户；
4. 新增按钮，但没有真实参与；
5. 新增 AI 输出，但用户没有更多主动权；
6. 星兽更漂亮，但身份仍不可认出；
7. Reality 信息更多，但同行关系断裂；
8. Crystal 数量增加，但来源不可追溯；
9. Archive 记录更多，但生命连续性不成立；
10. Sanctuary 更丰富，但用户没有长期关系；
11. 已有 Runtime 被重新创建；
12. 后续 Phase 的能力提前成为当前卖点。
